# 信息收集

渗透测试第一步:主机发现、端口扫描、子域名枚举、指纹识别与 OSINT。本文件命令均可直接复制,占位符用尖括号标注(如 `<目标IP>` `<域名>`)。

本文件工具:nmap、masscan、amass、sublist3r、theHarvester、dnsrecon、recon-ng、sherlock、whatweb、wafw00f、gowitness

## nmap — 端口扫描与服务识别的事实标准

来源:apt 包 `nmap`(/usr/bin/nmap)

### 主机发现(不扫端口)

```bash
nmap -sn 192.168.1.0/24                       # ping 扫描整个网段,只列出存活主机
nmap -sn -PE -PP -PS80,443 <目标IP>           # ICMP/ARP/TCP SYN 混合探测,绕过禁 ping 的主机
nmap -Pn -sn <目标IP>                         # 跳过主机发现,直接假定目标存活(防火墙丢 ping 时用)
nmap -sn 10.0.0.1-100 --exclude 10.0.0.25     # 扫一段地址并排除特定主机
```

### TCP/UDP 全端口扫描

```bash
nmap -p- --min-rate 5000 -T4 <目标IP> -oA allports          # TCP 全端口(0-65535),高速模式
nmap -sU --top-ports 100 --min-rate 1000 <目标IP>           # UDP 只扫最常见 100 端口(UDP 慢,别轻易全扫)
nmap -sS -p 1-1000 -v <目标IP>                               # 半开扫描前 1000 端口,较隐蔽(需 root)
```

### 服务版本 + 脚本扫描(精扫)

```bash
nmap -sV -sC -O -p 80,443,22,3389 <目标IP>     # 对开放端口做版本探测+默认脚本+操作系统识别
nmap -sV --version-intensity 5 -p 80 <目标IP>  # 加大版本探测强度(默认 2,最大 9,越慢越准)
nmap --script vuln -p 80,443 <目标IP>          # 跑漏洞类 NSE 脚本快速体检
nmap --script smb-vuln-ms17-010 -p 445 <目标IP> # 单点检测永恒之蓝(触发 IDS 高危告警,授权测试再用)
```

### 输出与复用(-oA 三格式)

```bash
nmap -sV -p- <目标IP> -oA results/目标名       # 同时生成 .nmap(可读)/.gnmap(可grep)/.xml(可入库)
grep Ports results/目标名.gnmap | awk -F/ '/open/{print $1, $7}'   # 从 gnmap 提取开放端口列表
nmap -sV -iL targets.txt -oA results/batch     # 从文件批量扫目标
```

参数速查:

- `-sn` — 只做主机发现,不扫端口
- `-Pn` — 跳过主机发现,假定目标存活
- `-p-` — 扫全部 65535 个 TCP 端口
- `-sS / -sT / -sU` — SYN 半开 / TCP 全连接 / UDP 扫描
- `-sV` — 服务版本探测;`-O` 操作系统识别;`-A` 等于 `-sV -O -sC --traceroute`
- `-sC` — 运行默认 NSE 脚本组
- `--script <脚本名/分类>` — 运行指定 NSE 脚本,如 vuln、auth、smb-vuln-*
- `--min-rate <数值>` — 强制最低发包速率(全端口提速用)
- `-T0~T5` — 时间模板,T4 常用,T0 最慢最隐蔽
- `-oA <前缀>` — 同时输出三种格式;-iL 读目标文件

注意:SYN 扫描(-sS)、UDP 扫描、操作系统识别(-O)均需 root;`--min-rate` 与 `-T5` 在窄带宽链路会丢包导致漏报;vuln/smb-vuln 类脚本会触发目标告警,仅在授权范围内使用。

## masscan — 极高速全网段端口扫描(先粗筛后交给 nmap 精扫)

来源:apt 包 `masscan`(/usr/bin/masscan)

```bash
masscan <目标IP> -p 1-65535 --rate=10000 --open-only -oL masscan.txt   # 全端口高速扫,只留开放端口
masscan 10.0.0.0/24 --rate=10000 --open-only -oL masscan.txt           # 扫整个 C 段
masscan -iL targets.txt -p 80,443,8080 --rate=5000 --banners           # 批量目标+常用 Web 端口+抓 banner
```

### 与 nmap 配合:masscan 粗筛 → nmap 精扫

```bash
# 第一步:masscan 秒级找出开放端口(输出格式:协议 端口 IP 时间戳)
masscan <目标IP> -p- --rate=10000 --open-only -oL masscan.txt

# 第二步:提取端口列表,逗号拼接后交给 nmap 做版本探测和脚本扫描
PORTS=$(awk '{print $3}' masscan.txt | sort -un | paste -sd,)        # 从结果提取开放端口号
nmap -sV -sC -p "$PORTS" <目标IP> -oA results/精扫                    # 只对开放端口精扫,省时间
```

参数速查:

- `-p <端口/范围>` — 目标端口,如 `80,443`、`1-65535`
- `--rate=<pps>` — 每秒发包数,万兆内网可到 100000,注意别打瘫链路
- `--open-only` — 只报告开放端口,过滤掉大量无响应记录
- `--banners` — 尝试抓取服务 banner
- `-iL <文件>` — 从文件读目标列表
- `--exclude <IP>` — 排除特定地址(如网关/监控设备,防止误伤)
- `-oL/-oJ/-oG` — 列表 / JSON / grep 友好格式输出
- `-e <网卡>` — 指定发包网卡(多网卡环境必配)
- `--router-mac <MAC>` — 指定网关 MAC(跨网段扫描丢包时排查用)

注意:masscan 以自有 TCP/IP 栈发原始包,必须 root 运行,且会绕过本机防火墙;它只判断开不开,不做可靠的服务识别,永远把结果交回 nmap 精扫;`--rate` 过高会打瘫目标或被运营商限流。

## amass — 深度子域名枚举与攻击面测绘(OWASP 项目)

来源:apt 包 `amass`(Kali 包装脚本 /usr/bin/amass,实际二进制 /usr/lib/amass/amass,当前 v5.1.1)

```bash
export http_proxy=http://10.211.55.2:2334 https_proxy=http://10.211.55.2:2334   # 联网数据源走代理
amass enum -passive -d <域名> -o amass_passive.txt       # 纯被动枚举(只查公开数据源,不碰目标)
amass enum -d <域名> -active -brute -w /usr/share/seclists/Discovery/DNS/bitquark-subdomains-top100000.txt -o amass_active.txt
# 主动模式:含证书透明、DNS 字典爆破,会直接向目标 DNS 发包
amass enum -d <域名> -r 8.8.8.8,1.1.1.1                  # 指定公共 DNS 解析器(防本机 DNS 污染)
amass db -list                                           # 查看本地已保存的枚举数据库
```

参数速查:

- `-d <域名>` — 目标域名(可逗号分隔多个)
- `-passive` — 只用被动数据源,不给目标留痕
- `-active` — 主动模式(含证书抓取、DNS 解析验证)
- `-brute` — 启用字典爆破子域名
- `-w <字典>` — 爆破字典路径,默认用内置小字典
- `-o <文件>` — 结果输出到文件
- `-r <DNS>` — 指定解析服务器
- `-bl <黑名单>` — 排除解析到这些地址的子域(过滤泛解析/CDN)
- `-timeout <秒>` — 单个数据源超时

注意:Kali 的 amass 包装脚本首次运行会 `sudo` 下载 libpostal 数据,失败则先手动 `sudo libpostal_data download all /var/lib/libpostal`;主动模式(-active)会向目标 DNS 发大量查询,隐蔽需求时只用 -passive。

## sublist3r — 轻量快速子域名枚举(聚合多个搜索引擎)

来源:apt 包 `sublist3r`(/usr/bin/sublist3r)

```bash
export http_proxy=http://10.211.55.2:2334 https_proxy=http://10.211.55.2:2334   # 依赖 Google/Bing 等外部源,走代理
sublist3r -d <域名> -o subs.txt                           # 默认聚合枚举,结果存文件
sublist3r -d <域名> -b -t 40                              # 加子域爆破,40 线程
sublist3r -d <域名> -p 80,443,8080 -v                     # 对发现的子域探测常见 Web 端口(-v 显示实时进度)
sublist3r -d <域名> -e google,bing,virustotal             # 只用指定数据源引擎
```

参数速查:

- `-d <域名>` — 目标域名(必填)
- `-b` — 启用子域爆破
- `-p <端口>` — 对发现的子域做端口检查,如 `80,443`
- `-t <线程>` — 爆破线程数,默认 30
- `-e <引擎>` — 指定数据源引擎,逗号分隔
- `-v` — 详细输出
- `-o <文件>` — 结果保存到文本文件
- `-n` — 输出无颜色(管道/日志友好)

注意:强依赖 Google/Bing 等外部搜索引擎,不走代理在受限网络下常返回空结果;结果不如 amass 全,胜在快,适合先跑一遍建立基线。

## theHarvester — 从公开渠道收集邮箱、子域、主机与人员信息(OSINT)

来源:apt 包 `theharvester`(当前 v4.11.1,/usr/bin/theHarvester)

```bash
export http_proxy=http://10.211.55.2:2334 https_proxy=http://10.211.55.2:2334   # 所有数据源都在线,走代理
theHarvester -d <域名> -b google,bing,crtsh,duckduckgo -l 500          # 收集邮箱+主机名,限制 500 条
theHarvester -d <域名> -b crtsh,dnsdumpster -f report                  # 结果同时存 HTML/JSON 报告
theHarvester -d <公司名> -b linkedin,github-code -n                     # 收集人员/邮箱并做 DNS 反查
theHarvester -d <域名> -b bing -t                                      # 对发现的 IP 做 Shodan 反查(需 API key)
```

参数速查:

- `-d <域名/公司名>` — 搜索目标(必填)
- `-b <数据源>` — 指定数据源:google、bing、crtsh、duckduckgo、dnsdumpster、linkedin、github-code、virustotal 等,逗号分隔
- `-l <数量>` — 结果条数上限,默认 500
- `-f <文件名>` — 保存 HTML/JSON 报告
- `-n` — 对发现的主机做 DNS 反向解析
- `-c` — 对主机做 DNS 暴力破解
- `-t` — 用 Shodan 反查发现的主机(需 /etc/theHarvester/api-keys.yaml 配 key)
- `-s` — 用 Shodan 查询发现的主机
- `-e <DNS服务器>` — 指定解析用 DNS
- `-S <起点>` — 从第 X 条结果开始翻页

注意:邮箱结果直接可用于钓鱼演练评估或弱口令字典构造;Shodan/部分源需在 `/etc/theHarvester/api-keys.yaml` 填 API key;Google 源易被验证码拦截,失败就换 bing/crtsh。

## dnsrecon — DNS 记录枚举、区域传输与子域爆破

来源:apt 包 `dnsrecon`(/usr/bin/dnsrecon)

```bash
dnsrecon -d <域名> -t std                                # 标准枚举:A/MX/NS/TXT/SRV 全套记录
dnsrecon -d <域名> -t axfr                               # 尝试对 NS 服务器做区域传输(配置错误时可拿全量记录)
dnsrecon -d <域名> -t brte -D /usr/share/seclists/Discovery/DNS/bitquark-subdomains-top100000.txt -n <DNS服务器IP>
# 用 seclists 字典爆破子域,并指定权威 NS 服务器
dnsrecon -d <域名> -t std -x dnsrecon.xml                # 结果存 XML(可导入其他工具)
dnsrecon -r 10.0.0.1-10.0.0.254                          # 对 IP 段做反向解析(找内网域名)
```

参数速查:

- `-d <域名>` — 目标域名
- `-t <类型>` — 枚举类型:`std` 标准、`axfr` 区域传输、`brte` 爆破、`rvl` 反向、`snoop` DNS 缓存探测、`zonewalk` DNSSEC 区遍历
- `-D <字典>` — brte 用的子域字典路径
- `-n <DNS服务器>` — 指定权威 NS 服务器
- `-r <IP范围>` — 反向解析范围,如 `10.0.0.1-10.0.0.254`
- `-x/-c/-j <文件>` — XML / CSV / JSON 格式输出
- `-a` — 标准枚举时顺带尝试 AXFR
- `-k` — 顺带查 crt.sh 证书数据
- `-f` — 爆破时过滤泛解析结果(解析到相同 IP 的通配域名)

注意:AXFR 失败是常态,成功即说明 DNS 配置严重失误;对公网域名爆破选 bitquark top100000 字典性价比最高,泛解析域名必须加 `-f` 过滤否则结果全是垃圾。

## recon-ng — 模块化 OSINT 侦察框架(带工作区与数据库)

来源:apt 包 `recon-ng`(/usr/bin/recon-ng)

```bash
recon-ng -w <项目名>                 # 启动并创建/加载独立工作区(数据隔离存 SQLite)
recon-ng -w <项目名> -r tasks.rc     # 按资源文件批量执行命令(无人值守跑全套侦察)
```

### 交互模式典型流程(进入 recon-ng 后逐条输入)

```bash
marketplace refresh                  # 刷新模块市场索引
marketplace install recon/domains-hosts/hackertarget    # 安装子域枚举模块(示例)
modules search hackertarget          # 按关键词搜模块
modules load recon/domains-hosts/hackertarget           # 加载模块
options set SOURCE <域名>            # 设置模块的数据来源参数
info                                 # 检查模块参数是否配齐
run                                  # 执行,结果自动入库
db schema                           # 查看当前库结构(hosts/contacts/domains 等表)
db query select * from hosts         # 直接 SQL 查询已收集的主机
back                                 # 退出当前模块
```

参数速查:

- `-w <名称>` — 启动时创建/加载工作区
- `-r <文件>` — 从资源文件批量执行命令
- `marketplace search/install` — 搜索/安装模块
- `modules search/load` — 查找/加载模块
- `options set/show` — 设置/查看模块参数(SOURCE 最常用)
- `run` — 执行当前模块
- `db schema / db query / hosts / contacts` — 查库结构与数据(可写 SQL)
- `workspaces list/create/select` — 多项目管理
- `--stealth` — 启动时不发任何外部请求(纯离线整理数据)

注意:所有结果按工作区落库在 `~/.recon-ng/workspaces/<项目名>/`,换项目先 `workspaces select` 防止数据混写;部分模块需要 API key,在 `keys add <服务名> <key>` 配置;国内网络装模块前记得在 shell 里 export 代理。

## sherlock — 跨 400+ 平台的用户名存在性查询(找人/找关联账号)

来源:apt 包 `sherlock`(/usr/bin/sherlock)

```bash
export http_proxy=http://10.211.55.2:2334 https_proxy=http://10.211.55.2:2334   # 全部目标站点在线,走代理
sherlock <用户名> --timeout 10                            # 单用户名全平台查询
sherlock <用户名> --site github,gitlab,instagram --print-found   # 只查指定平台,只显示命中
sherlock <用户名> -o result.txt --csv                     # 文本+CSV 双格式保存
sherlock <用户名> --proxy http://10.211.55.2:2334         # 指定代理(与 export 二选一)
```

参数速查:

- `<用户名>` — 要查询的用户名,可一次给多个
- `--site <站点>` — 限定平台,逗号分隔,如 `github,twitter`
- `--timeout <秒>` — 单站点超时(默认 5,网络差可调大)
- `--print-found` — 只输出命中的站点(默认全输出,噪点多)
- `--print-all` — 输出全部站点含未命中
- `-o/--output <文件>` — 保存文本结果
- `--csv / --xlsx` — 另存 CSV / Excel
- `--proxy <URL>` — 走 HTTP 代理
- `--tor / --unique-tor` — 走 Tor(需本地 Tor 服务)
- `--local` — 用本地内置站点清单,不联网拉最新

注意:命中≠同一人,重名率高,建议结合 whatweb/邮箱后缀交叉验证;批量查多人时加 `--timeout 5` 并避免高频触发目标站点风控。

## whatweb — 网站技术栈指纹识别(语言/CMS/框架/服务器)

来源:apt 包 `whatweb`(/usr/bin/whatweb)

```bash
whatweb <目标URL>                              # 基础识别:一次请求判断常用组件
whatweb -a 3 <目标URL>                         # 侵略级别 3:额外拉 favicon/robots 等增强判断
whatweb -i urls.txt --no-errors                # 批量扫 URL 列表,跳过报错目标
whatweb -a 3 <目标URL> --log-json fp.json      # 结果存 JSON 便于入库比对
whatweb <目标URL> -U "Mozilla/5.0" --proxy http://10.211.55.2:2334   # 伪装 UA 并走代理
```

参数速查:

- `<URL>` — 目标网址,可跟多个
- `-a <1-4>` — 侵略级别:1 隐蔽(默认),3 增强,4 会尝试更多路径(可能触发告警)
- `-i <文件>` — 从文件批量读 URL
- `-U <UA>` — 自定义 User-Agent
- `--proxy <主机:端口>` — 走代理请求
- `--no-errors` — 批量扫描时忽略超时/报错目标
- `--log-json <文件>` — JSON 格式日志
- `-v` — 详细输出(含请求过程)
- `--color=never` — 关闭颜色输出(管道友好)

注意:`-a 4` 会额外请求多个路径,目标可能记录为扫描行为;结果只做初判,CMS 版本疑似过旧时用对应专用工具(如 wpscan)复核。

## wafw00f — Web 应用防火墙(WAF)产品识别

来源:apt 包 `wafw00f`(/usr/bin/wafw00f)

```bash
wafw00f <目标URL>                             # 常规检测,输出命中的 WAF
wafw00f -a <目标URL>                          # 匹配全部签名,识别多层 WAF(如 CDN+源站各一层)
wafw00f -i urls.txt -v                        # 批量检测并显示探测过程
wafw00f -l                                    # 列出所有可识别的 WAF 产品(先确认支持范围)
wafw00f <目标URL> -p http://10.211.55.2:2334  # 通过代理检测
```

参数速查:

- `<URL>` — 目标网址
- `-a` — 匹配所有签名,不止步于第一个命中
- `-v` — 详细输出,显示每个探测请求
- `-r` — 不跟随 3xx 跳转(直接测入口域名时用)
- `-t <WAF名>` — 只测指定 WAF(名字来自 `-l` 输出)
- `-l` — 列出支持的 WAF 清单
- `-i <文件>` — 批量目标文件
- `-p <代理>` — HTTP 代理
- `-H <头>` — 附加自定义请求头
- `-T <秒>` — 请求超时

注意:识别出 WAF(如 Cloudflare/ModSecurity)后,后续注入类工具需配套绕过参数(如 sqlmap `--tamper`),否则纯打日志;探测请求本身会被 WAF 记录,隐蔽测试时控制频率。

## gowitness — 网站批量截图与响应信息留存(可视化攻击面)

来源:apt 包 `gowitness`(当前 v3,/usr/bin/gowitness)

```bash
# 准备 URL 列表文件(每行一个,自动补 http/https)
cat > urls.txt <<EOF
http://<目标IP>
http://<目标IP>:8080
https://<域名>
EOF

gowitness scan file -f urls.txt --write-db --screenshot-path ./shots    # 批量截图并存 SQLite 库
gowitness scan cidr -c 10.0.0.0/24 --port 80,443,8080 --threads 20      # 直接扫网段常见 Web 端口
gowitness report generate --db-uri gowitness.sqlite3                    # 生成静态 HTML 报告
gowitness report server --port 7171 --db-uri gowitness.sqlite3          # 起本地 Web 界面浏览结果(浏览器开 http://127.0.0.1:7171)
```

参数速查:

- `scan file -f <文件>` — 从 URL 文件批量截图(也支持 stdin:`-f -`)
- `scan cidr -c <网段>` — 扫整个网段的 Web 服务
- `--port <端口>` — cidr 模式指定探测端口
- `--threads <N>` — 并发线程数
- `--no-http / --no-https` — 关闭自动补某协议
- `--write-db` — 结果写 SQLite(默认只存截图,不写库)
- `--write-jsonl <文件>` — 追加 JSONL 输出(便于管道处理)
- `--screenshot-path <目录>` — 截图存放目录
- `--save-content` — 顺带保存页面源码
- `report server/generate` — Web 界面查看 / 生成静态报告

注意:截图依赖无头 Chrome,首次在无显示环境运行需系统已装 chromium(apt 已带依赖);目标多时用 `--threads` 控制并发避免打满出口带宽;内网大网段扫描前先用 nmap/masscan 收敛目标再截图,效率高得多。
衔接:内网大网段可先用 05 号的 fscan 一键收敛存活与开放端口,把 Web 服务整理成 urls.txt 再喂本工具批量截图。
